# 5월 식품들의 총매출 조회하기

## 문제 요약
> `FOOD_PRODUCT`와 `FOOD_ORDER`를 조인해 **생산일자(`PRODUCE_DATE`)가 2022년 5월**인 주문만 대상으로, **상품별 총매출(PRICE × AMOUNT)**을 집계해 정렬한다.

## 느낀점
>
- 배운거 잘 정리해두자
(집계함수의 특징)

## 코드
```sql
SELECT FP.PRODUCT_ID, FP.PRODUCT_NAME, SUM(FP.PRICE * FO.AMOUNT) AS TOTAL_SALES
FROM FOOD_PRODUCT FP
JOIN FOOD_ORDER FO ON FP.PRODUCT_ID = FO.PRODUCT_ID
WHERE FO.PRODUCE_DATE LIKE '2022-05%'
GROUP BY FP.PRODUCT_ID, FP.PRODUCT_NAME
ORDER BY TOTAL_SALES DESC, FP.PRODUCT_ID;
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

| 질문 | 답변 |
|------|------|
| FOOD_ORDER에 같은 PRODUCT_ID가 여러 행으로 존재해도 집계가 되나? | 가능. `FOOD_ORDER`는 (주문행 단위로) `PRODUCT_ID`가 1개이고, 같은 상품이 여러 주문행에 반복될 수 있다. `GROUP BY (PRODUCT_ID...)`로 묶으면 상품별로 합쳐진다. |
| 집계함수(SUM)랑 비집계 컬럼을 같이 SELECT할 때 GROUP BY는 왜 필요해? | 표준 SQL 기준으로, 집계되지 않은 컬럼을 SELECT에 포함하면 **그 컬럼이 그룹 기준에 포함**되어야 한다(또는 윈도우/집계로 감싸야 함). 그렇지 않으면 DB는 어떤 값을 대표로 보여줘야 할지 모호해진다. |
| `GROUP BY PRODUCT_ID`만 하고 `PRODUCT_NAME`을 SELECT해도 될까? | `PRODUCT_ID → PRODUCT_NAME`이 1:1로 보장(함수적 종속)되면 논리적으로는 가능해 보이지만, DB/설정마다 허용 여부가 달라 코테에선 안전하게 `PRODUCT_NAME`도 GROUP BY에 포함시키는 편이 정석이다. 더 깔끔하게는 `PRODUCT_ID`로 먼저 집계한 뒤 결과를 `FOOD_PRODUCT`와 조인해 이름을 붙인다. |

### 실수했던 부분

**1. 조건 컬럼 혼동 (생산일자 vs 출고일자)**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `OUT_DATE`로 5월 조건을 걸기 | 문제 요구는 `PRODUCE_DATE`가 2022년 5월 |

**2. GROUP BY 누락**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `SUM(...)` + `PRODUCT_ID/NAME`를 같이 SELECT하면서 GROUP BY 없음 | 상품별 집계를 원하면 `GROUP BY PRODUCT_ID, PRODUCT_NAME` 필요 |

**3. DATE 타입에 LIKE 사용 주의**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `PRODUCE_DATE LIKE '2022-05%'` (암묵 변환 의존) | 날짜 범위 조건(예: 2022-05-01 이상, 2022-06-01 미만) |

## AI 코드 리뷰

### 개선할 점

1. **날짜 필터는 범위로 처리**: DATE 컬럼에 `LIKE`를 쓰면 DB/설정에 따라 암묵적 형변환에 의존할 수 있고, 인덱스 활용에도 불리할 수 있다.
2. **집계 단계와 차원(이름/가격) 붙이기 분리**: `PRODUCT_ID`로만 먼저 집계한 뒤, `FOOD_PRODUCT`와 조인하면 읽기 쉽고 “왜 GROUP BY에 NAME까지 넣어야 하지?” 같은 고민도 자연스럽게 사라진다.

## 수정된 코드
```sql
SELECT
    P.PRODUCT_ID,
    P.PRODUCT_NAME,
    P.PRICE * S.TOTAL_AMOUNT AS TOTAL_SALES
FROM (
    SELECT
        PRODUCT_ID,
        SUM(AMOUNT) AS TOTAL_AMOUNT
    FROM FOOD_ORDER
    WHERE PRODUCE_DATE >= TO_DATE('2022-05-01', 'YYYY-MM-DD')
      AND PRODUCE_DATE <  TO_DATE('2022-06-01', 'YYYY-MM-DD')
    GROUP BY PRODUCT_ID
) S
JOIN FOOD_PRODUCT P
  ON P.PRODUCT_ID = S.PRODUCT_ID
ORDER BY TOTAL_SALES DESC, P.PRODUCT_ID ASC;
```
