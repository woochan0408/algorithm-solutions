# 오프라인/온라인 판매 데이터 통합하기
## 문제 요약
> ONLINE_SALE과 OFFLINE_SALE 테이블에서 2022년 3월 판매 데이터를 통합하여 출력. OFFLINE_SALE의 USER_ID는 NULL로 표시. 판매일 → 상품ID → 유저ID 오름차순 정렬.

## 느낀점
>
- UNION 키워드를 몰라서 틀렸다. (개념정리 해두자)
- SQL.. 어렵다.

## 코드

```sql
SELECT DATE_FORMAT(SALES_DATE, "%Y-%m-%d") AS SALES_DATE, PRODUCT_ID, USER_ID, SALES_AMOUNT
FROM ONLINE_SALE O
WHERE SALES_DATE >= "2022-03-01" AND SALES_DATE < "2022-03-31"
UNION ALL 
SELECT DATE_FORMAT(SALES_DATE, "%Y-%m-%d") AS SALES_DATE, PRODUCT_ID, NULL AS USER_ID, SALES_AMOUNT
FROM OFFLINE_SALE OFF
WHERE SALES_DATE >= "2022-03-01" AND SALES_DATE <= "2022-03-31"
ORDER BY SALES_DATE, PRODUCT_ID, USER_ID
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

| 질문 | 답변 |
|------|------|
| 두 테이블 결과를 합치는 방법 | `UNION ALL` 사용 (중복 유지, 성능 좋음) |
| 없는 컬럼 처리 | `NULL AS 컬럼명`으로 채움 |

### 실수했던 부분

**1. DATE_FORMAT 대상 컬럼 오류**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `DATE_FORMAT(SALES_AMOUNT, ...)` | `DATE_FORMAT(SALES_DATE, ...)` |

**2. WHERE 조건 누락**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| 첫 번째 SELECT에 WHERE 없음 | 양쪽 SELECT 모두 WHERE 필요 |

**3. 날짜 범위 연산자 불일치**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `< "2022-03-31"` (31일 제외) | `<= "2022-03-31"` 또는 `< "2022-04-01"` |

## AI 코드 리뷰

### 개선할 점

1. **날짜 범위 통일**: 첫 번째 SELECT가 아직 `<` 사용 중. `<=`로 수정 필요
2. **불필요한 테이블 별칭**: `O`, `OFF` 별칭을 선언했지만 사용하지 않음. 제거
3. **DATE_FORMAT 불필요**: 프로그래머스에서 DATE 타입은 자동으로 `YYYY-MM-DD` 출력됨
4. **날짜 필터 간소화**: `LIKE '2022-03%'` 또는 `YEAR()/MONTH()` 함수로 더 간결하게 표현 가능

## 수정된 코드

```sql
SELECT SALES_DATE, PRODUCT_ID, USER_ID, SALES_AMOUNT
FROM ONLINE_SALE
WHERE SALES_DATE LIKE '2022-03%'

UNION ALL

SELECT SALES_DATE, PRODUCT_ID, NULL AS USER_ID, SALES_AMOUNT
FROM OFFLINE_SALE
WHERE SALES_DATE LIKE '2022-03%'

ORDER BY SALES_DATE, PRODUCT_ID, USER_ID
```
