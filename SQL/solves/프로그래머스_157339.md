# 특정 기간동안 대여 가능한 자동차들의 대여비용 구하기

## 문제 요약
> 세단/SUV 중 2022년 11월에 대여 가능한 차량의 30일 대여 금액(할인 적용)이 50만~200만원인 차량 조회

## 느낀점
>
- 대가리 박으면서 어거지로 푼 문제
- 문제가 참 좋다. 꼭 2번 이상 더 풀어보자.

---

## 코드
```sql
WITH P AS (
    SELECT CAR_TYPE, DISCOUNT_RATE
    FROM CAR_RENTAL_COMPANY_DISCOUNT_PLAN
    WHERE DURATION_TYPE = '30일 이상'
    ),
    H AS (
    SELECT CAR_ID, COUNT(*) AS CNT
    FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
    WHERE START_DATE <= '2022-11-30' AND END_DATE >= '2022-11-01'
    GROUP BY CAR_ID 
    )
SELECT C.CAR_ID, C.CAR_TYPE, FLOOR(DAILY_FEE*30*0.01*(100-P.DISCOUNT_RATE)) AS FEE
FROM CAR_RENTAL_COMPANY_CAR C
JOIN P ON P.CAR_TYPE = C.CAR_TYPE
LEFT JOIN H ON H.CAR_ID = C.CAR_ID
WHERE FLOOR(DAILY_FEE*30*0.01*(100-P.DISCOUNT_RATE)) >= 500000
    AND FLOOR(DAILY_FEE*30*0.01*(100-P.DISCOUNT_RATE)) < 2000000
    AND H.CNT IS NULL
    AND (C.CAR_TYPE = '세단' OR C.CAR_TYPE = 'SUV')
ORDER BY FEE DESC, CAR_TYPE, CAR_ID
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

#### CASE WHEN — 조건에 따라 다른 값 반환
범위별로 다른 할인율을 적용해야 할 때 `CASE WHEN`을 사용할 수 있다. 이 문제에서는 CTE로 '30일 이상' 할인율만 필터링했기 때문에 직접 사용하지는 않았지만, 여러 범위를 동시에 다뤄야 할 때 핵심 구문이다.
```sql
CASE
    WHEN 대여기간 >= 90 THEN '90일 이상'
    WHEN 대여기간 >= 30 THEN '30일 이상'
    WHEN 대여기간 >= 7  THEN '7일 이상'
    ELSE '할인없음'
END
```

#### CTE 문법 — 여러 개 쓸 때 WITH는 한 번만
```sql
-- ❌ WITH를 두 번 씀
WITH A AS (...) WITH B AS (...)

-- ✅ 쉼표로 연결
WITH A AS (...),
     B AS (...)
SELECT ...
```

#### NOT IN / NOT EXISTS vs LEFT JOIN + IS NULL
"대여 중인 차량을 제외"하는 3가지 방법이 있다.

**NOT IN** — 서브쿼리 결과에 없는 것만 조회
```sql
WHERE CAR_ID NOT IN (SELECT CAR_ID FROM 대여기록 WHERE 겹침조건)
```

**NOT EXISTS** — 서브쿼리에 존재하지 않는 것만 조회
```sql
WHERE NOT EXISTS (
    SELECT 1 FROM 대여기록 H
    WHERE H.CAR_ID = C.CAR_ID AND 겹침조건
)
```

**LEFT JOIN + IS NULL** — 매칭 안 되는 행만 남김 (이번에 사용한 방법)
```sql
LEFT JOIN 대여기록 H ON H.CAR_ID = C.CAR_ID
WHERE H.CAR_ID IS NULL
```

LEFT JOIN을 사용한 이유: 대여 기록이 있는 차량을 CTE로 먼저 집계(GROUP BY + COUNT)한 뒤, LEFT JOIN으로 매칭되지 않는 차량(= 대여 가능 차량)을 찾으려 했기 때문. 단, `GROUP BY + COUNT(*)`는 기록이 존재하는 행만 생성하므로 `CNT = 0`은 불가능하고, `IS NULL`로 체크해야 한다.

#### 기간 겹침 판정 공식
두 기간 [A_start, A_end]와 [B_start, B_end]가 겹치는 조건:
```sql
A_start <= B_end AND A_end >= B_start
```
`BETWEEN`이나 `OR`로 하면 한 기간이 다른 기간을 완전히 감싸는 케이스를 놓칠 수 있다.

#### ROUND / CEIL / FLOOR / TRUNCATE
```sql
ROUND(123.456, 1)    -- 123.5 (반올림)
CEIL(123.001)        -- 124   (올림)
FLOOR(123.999)       -- 123   (내림)
TRUNCATE(123.456, 1) -- 123.4 (자릿수 지정 버림, MySQL 전용)
```

### 실수했던 부분

**1. CTE 문법 오류 (WITH 중복 + 괄호 누락)**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `WITH P AS (...) WITH H AS (...)` | `WITH P AS (...), H AS (...)` |
| 첫 CTE 닫는 괄호 `)` 누락 | 각 CTE를 `)`로 닫고 `,`로 구분 |

**2. SQL 실행 순서 — WHERE를 GROUP BY 뒤에 작성**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `GROUP BY CAR_ID WHERE ...` | `WHERE ... GROUP BY CAR_ID` |

**3. HAVING을 GROUP BY 없이 사용**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `HAVING FEE >= 500000` (GROUP BY 없이) | `WHERE 계산식 >= 500000` 또는 서브쿼리로 감싸서 WHERE |

**4. FEE 계산식 — 할인 금액 vs 할인 적용 후 금액**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `DAILY_FEE * 30 * 0.01 * DISCOUNT_RATE` (할인 금액) | `DAILY_FEE * 30 * 0.01 * (100 - DISCOUNT_RATE)` (할인 적용 후) |

**5. WHERE와 SELECT의 계산식 불일치**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| SELECT: `(100-DISCOUNT_RATE)`, WHERE: `DISCOUNT_RATE` | 동일한 계산식 사용 |

**6. 금액 범위 오기입**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `>= 300000 AND < 500000` | `>= 500000 AND < 2000000` |

**7. 기간 겹침 조건 — OR / BETWEEN 사용**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `START_DATE >= '11-01' OR END_DATE <= '11-30'` | `START_DATE <= '2022-11-30' AND END_DATE >= '2022-11-01'` |
| `BETWEEN`도 감싸는 케이스 놓침 | AND 조건이 모든 겹침 케이스 커버 |

**8. JOIN으로 "없는 차량" 찾기 불가**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `JOIN H` + `CNT = 0` | `LEFT JOIN H` + `H.CNT IS NULL` |

**9. 세단/SUV 필터 누락**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| CAR_TYPE 조건 없음 | `AND (C.CAR_TYPE = '세단' OR C.CAR_TYPE = 'SUV')` |

## AI 코드 리뷰

### 개선할 점

1. **IN 연산자 활용**: `C.CAR_TYPE = '세단' OR C.CAR_TYPE = 'SUV'`보다 `C.CAR_TYPE IN ('세단', 'SUV')`가 간결하고 확장성이 좋다.

2. **WHERE 계산식 중복 제거**: `FLOOR(...)` 계산식이 WHERE에 2번 반복되고 있다. 서브쿼리로 감싸면 `FEE` 별칭으로 필터링할 수 있어 가독성이 좋아진다.

3. **NOT IN 방식이 더 간결**: LEFT JOIN + IS NULL 방식도 동작하지만, 이 문제에서는 CTE에서 GROUP BY + COUNT까지 할 필요 없이 NOT IN으로 해당 CAR_ID를 직접 제외하는 것이 더 직관적이다.

4. **ORDER BY 정렬 방향 명시**: 문제에서 CAR_TYPE은 오름차순, CAR_ID는 내림차순을 요구하는데, 현재 코드에서 방향이 명시되지 않은 컬럼이 있다.

## 수정된 코드
```sql
SELECT CAR_ID, CAR_TYPE, FEE
FROM (
    SELECT C.CAR_ID, C.CAR_TYPE,
           FLOOR(C.DAILY_FEE * 30 * (100 - P.DISCOUNT_RATE) / 100) AS FEE
    FROM CAR_RENTAL_COMPANY_CAR C
    JOIN CAR_RENTAL_COMPANY_DISCOUNT_PLAN P
        ON P.CAR_TYPE = C.CAR_TYPE
        AND P.DURATION_TYPE = '30일 이상'
    WHERE C.CAR_TYPE IN ('세단', 'SUV')
        AND C.CAR_ID NOT IN (
            SELECT CAR_ID
            FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
            WHERE START_DATE <= '2022-11-30'
                AND END_DATE >= '2022-11-01'
        )
) T
WHERE FEE >= 500000 AND FEE < 2000000
ORDER BY FEE DESC, CAR_TYPE ASC, CAR_ID DESC;
```
