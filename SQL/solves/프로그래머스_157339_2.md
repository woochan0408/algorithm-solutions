# 특정 기간동안 대여 가능한 자동차들의 대여비용 구하기

## 문제 요약
> 세단/SUV 중 2022년 11월에 대여 가능한 차량의 30일 대여 금액(할인 적용)이 50만~200만원 미만인 차량 조회

## 코드
```sql
WITH H AS (
    SELECT DISTINCT CAR_ID
    FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
    WHERE START_DATE <= '2022-11-30' AND END_DATE >= '2022-11-01'
)
SELECT C.CAR_ID, C.CAR_TYPE, ROUND(0.01*30*(100-P.DISCOUNT_RATE)*C.DAILY_FEE) AS FEE
FROM CAR_RENTAL_COMPANY_CAR C
LEFT JOIN 
(
    SELECT CAR_TYPE, DISCOUNT_RATE
    FROM CAR_RENTAL_COMPANY_DISCOUNT_PLAN
    WHERE DURATION_TYPE = '30일 이상'
) P ON C.CAR_TYPE = P.CAR_TYPE
WHERE C.CAR_TYPE IN ('세단', 'SUV') 
    AND 0.01*30*(100-P.DISCOUNT_RATE)*C.DAILY_FEE BETWEEN 500000 AND 1999999 
    AND NOT EXISTS (SELECT 1 FROM H WHERE H.CAR_ID = C.CAR_ID)
ORDER BY FEE DESC, CAR_TYPE, CAR_ID DESC
```

## 질문 & 실수 정리

### 새로 배운 것

#### 1. "대여 가능" = 겹치는 기록이 없는 차량
날짜 범위가 겹치는 조건 `START_DATE <= 기간끝 AND END_DATE >= 기간시작`으로 **대여 중인 차량**을 먼저 구한 뒤, `NOT EXISTS` 또는 `NOT IN`으로 **제외**하는 패턴이 핵심이다. 처음에는 겹치는 조건을 대여 "가능"으로 착각하여 로직이 반대였다.

#### 2. 기준 테이블 선택의 중요성
대여 기록(HISTORY)을 기준으로 시작하면, 대여 이력이 아예 없는 차량(당연히 대여 가능)이 결과에서 빠진다. 차량 정보(CAR) 테이블을 기준으로 시작해야 모든 차량을 포함할 수 있다.

#### 3. NOT IN vs NOT EXISTS
- **NOT IN**: 서브쿼리가 값 목록을 만들고, 그 목록에 없는지 비교. 단, 목록에 **NULL이 하나라도 있으면 모든 결과가 사라진다** (SQL 3값 논리).
- **NOT EXISTS**: 바깥 쿼리의 각 행마다 상관 서브쿼리를 실행해 존재 여부만 확인. **NULL 영향을 받지 않아 더 안전**하다.
- 컬럼이 NOT NULL 확실하면 NOT IN도 괜찮지만, 안전하게 가려면 NOT EXISTS를 습관화하는 게 좋다.

#### 4. 상관 서브쿼리 (Correlated Subquery)
```sql
NOT EXISTS (SELECT 1 FROM H WHERE H.CAR_ID = C.CAR_ID)
```
바깥 쿼리가 한 행씩 처리할 때, 그 행의 `C.CAR_ID` 값이 서브쿼리 안으로 전달된다. 매 행마다 서브쿼리가 다시 평가되기 때문에, `C.CAR_ID`는 "현재 처리 중인 행"의 값이 된다. `SELECT 1`이든 `SELECT *`이든 상관없이 행의 존재 여부만 판단한다.

#### 5. NOT EXISTS 서브쿼리의 SELECT 값은 무의미
```sql
NOT EXISTS (SELECT 1 FROM H WHERE H.CAR_ID = C.CAR_ID)
```
`NOT EXISTS`는 서브쿼리가 반환하는 **값**은 전혀 보지 않고, **행이 존재하느냐 아니냐**만 판단한다. 따라서 `SELECT 1`, `SELECT 2`, `SELECT *`, `SELECT 'hello'` 모두 결과가 동일하다. `SELECT 1`은 관례적으로 "아무 값이나 넣은 것"일 뿐 특별한 의미는 없다.

#### 6. FEE 계산 시 % → 소수 변환
할인율이 8%일 때 `30 * (100 - 8) * 25000 = 69,000,000`으로 실제 금액과 100배 차이난다. `0.01`을 곱하거나 `/100`으로 나눠야 올바른 결과가 나온다.

#### 7. CTE 컬럼 참조 주의

#### 8. LEFT JOIN vs INNER JOIN 선택
INNER JOIN은 양쪽 테이블 모두에 매칭되는 행만 반환한다. 매칭이 없는 행은 결과에서 아예 제외된다. 반면 LEFT JOIN은 왼쪽 테이블의 모든 행을 유지하고, 매칭이 없으면 NULL로 채운다. 이 문제에서는 세단/SUV의 할인 정책이 반드시 존재하므로 INNER JOIN이 의미적으로 정확하고, NULL 방어도 불필요해진다.
CTE에서 `SELECT DISTINCT CAR_ID`만 선택했다면, CTE를 참조하는 곳에서 `H.CAR_TYPE` 같은 존재하지 않는 컬럼을 사용할 수 없다. CTE에 정의된 컬럼만 사용 가능하다.

### 실수했던 부분

**1. 단순 문법 실수들**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `SELECT DISTINCT CAR_ID,` (trailing comma) | `SELECT DISTINCT CAR_ID` |
| `FROM CAR_RENTAL_COMPANY_CAR` (별칭 누락) | `FROM CAR_RENTAL_COMPANY_CAR C` |
| `NOT EXIST` | `NOT EXISTS` |
| `CAR_ID NOT EXISTS (...)` | `NOT EXISTS (...)` — 앞에 컬럼명 X |
| `ORDER BY ... CAR_ID` (ASC) | `ORDER BY ... CAR_ID DESC` |

## AI 코드 리뷰

### 개선할 점

1. **LEFT JOIN → INNER JOIN**: 세단/SUV만 필터링하므로 할인 정책이 반드시 존재한다. LEFT JOIN 대신 INNER JOIN을 쓰는 것이 의미적으로 정확하고, 불필요한 NULL 가능성도 제거된다.

2. **서브쿼리 → JOIN ON 조건 통합**: 할인 정책 서브쿼리를 별도로 만들지 않고, INNER JOIN의 ON 조건에 `DURATION_TYPE = '30일 이상'`을 직접 넣으면 더 간결하다.

3. **FEE 계산 순서**: `0.01 * 30 * (100 - DISCOUNT_RATE) * DAILY_FEE`보다 `DAILY_FEE * 30 * (100 - DISCOUNT_RATE) / 100`이 정수 연산으로 처리되어 부동소수점 이슈를 방지할 수 있다.

4. **CTE 이름**: `H`보다 `UNAVAILABLE`처럼 의미가 드러나는 이름이 가독성에 좋다.

## 수정된 코드
```sql
WITH UNAVAILABLE AS (
    SELECT DISTINCT CAR_ID
    FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
    WHERE START_DATE <= '2022-11-30' 
      AND END_DATE >= '2022-11-01'
)
SELECT 
    C.CAR_ID, 
    C.CAR_TYPE, 
    ROUND(C.DAILY_FEE * 30 * (100 - P.DISCOUNT_RATE) / 100) AS FEE
FROM CAR_RENTAL_COMPANY_CAR C
INNER JOIN CAR_RENTAL_COMPANY_DISCOUNT_PLAN P 
    ON C.CAR_TYPE = P.CAR_TYPE 
    AND P.DURATION_TYPE = '30일 이상'
WHERE C.CAR_TYPE IN ('세단', 'SUV') 
    AND NOT EXISTS (
        SELECT 1 
        FROM UNAVAILABLE U 
        WHERE U.CAR_ID = C.CAR_ID
    )
    AND ROUND(C.DAILY_FEE * 30 * (100 - P.DISCOUNT_RATE) / 100) BETWEEN 500000 AND 1999999
ORDER BY FEE DESC, C.CAR_TYPE ASC, C.CAR_ID DESC
```
