# 업그레이드 된 아이템 구하기

## 문제 요약
> RARE 희귀도를 가진 아이템의 다음 업그레이드 아이템(자식)의 ID, 이름, 희귀도를 조회하고 ID 내림차순 정렬

## 느낀점
>
- 오늘 푼 첫 문제라 그런지 뇌가 잘 돌아가서 잘 풀었다.
- 

## 코드
```sql
SELECT ITEM_ID, ITEM_NAME, RARITY
FROM ITEM_INFO I
WHERE ITEM_ID IN (
    SELECT T.ITEM_ID
    FROM ITEM_TREE T
    LEFT JOIN ITEM_INFO I ON T.PARENT_ITEM_ID = I.ITEM_ID
    WHERE I.RARITY = 'RARE'
)
ORDER BY ITEM_ID DESC
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

| 질문 | 답변 |
|------|------|
| LEFT/RIGHT JOIN은 ON의 컬럼 순서에 따라 달라지는가? | ON의 컬럼 순서는 무관하고, FROM/JOIN 뒤에 오는 테이블 위치가 기준이다 |

## AI 코드 리뷰

### 개선할 점

1. **별칭(alias) 충돌**: 외부 쿼리와 서브쿼리 모두 `ITEM_INFO`에 같은 별칭 `I`를 사용하고 있다. 서브쿼리 내부에서 `I`가 재정의되어 현재는 정상 동작하지만, 유지보수 시 혼동을 일으킬 수 있으므로 서로 다른 별칭을 사용하는 것이 좋다.

2. **LEFT JOIN → INNER JOIN**: 서브쿼리에서 `LEFT JOIN`을 사용했지만, `WHERE I.RARITY = 'RARE'` 조건이 NULL을 걸러내므로 사실상 `INNER JOIN`과 동일하게 동작한다. 의도를 명확히 하기 위해 `INNER JOIN`(또는 `JOIN`)을 사용하는 것이 적절하다.

## 수정된 코드
```sql
SELECT I.ITEM_ID, I.ITEM_NAME, I.RARITY
FROM ITEM_INFO I
WHERE I.ITEM_ID IN (
    SELECT T.ITEM_ID
    FROM ITEM_TREE T
    JOIN ITEM_INFO P ON T.PARENT_ITEM_ID = P.ITEM_ID
    WHERE P.RARITY = 'RARE'
)
ORDER BY I.ITEM_ID DESC
```
