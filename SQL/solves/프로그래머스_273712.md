# 업그레이드 할 수 없는 아이템 구하기

## 문제 요약
> ITEM_TREE에서 다른 아이템의 PARENT가 아닌 아이템(리프 노드)의 ID, 이름, 희귀도를 ID 내림차순으로 출력

## 느낀점
>
- NULL값 처리의 중요성..
- 정리한 내용 여러 번 읽어보자. 

## 코드
```sql
SELECT I.ITEM_ID, I.ITEM_NAME, I.RARITY
FROM ITEM_INFO I
WHERE ITEM_ID NOT IN (
    SELECT PARENT_ITEM_ID
    FROM ITEM_TREE
    WHERE PARENT_ITEM_ID IS NOT NULL
)
ORDER BY ITEM_ID DESC
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

#### 1. `NOT IN` 서브쿼리에 NULL이 포함되면 왜 결과가 0건인가?

SQL에서 `NOT IN`은 내부적으로 각 값과 `!=` 비교를 `AND`로 연결한다.

```sql
-- 이 쿼리는
WHERE ITEM_ID NOT IN (0, 1, NULL)

-- 내부적으로 이렇게 평가된다
WHERE ITEM_ID != 0 AND ITEM_ID != 1 AND ITEM_ID != NULL
```

여기서 `ITEM_ID != NULL`은 항상 **UNKNOWN**을 반환한다. SQL의 3값 논리(TRUE, FALSE, UNKNOWN)에서 `TRUE AND UNKNOWN`은 **UNKNOWN**이고, `WHERE`절은 **TRUE인 행만** 반환하므로 모든 행이 필터링된다.

#### 2. 왜 `IN`에서는 NULL이 문제가 되지 않는가?

`IN`은 `OR`로 연결된다.

```sql
WHERE ITEM_ID IN (0, 1, NULL)
-- → ITEM_ID = 0 OR ITEM_ID = 1 OR ITEM_ID = NULL
```

`TRUE OR UNKNOWN`은 **TRUE**이므로, 매칭되는 값이 하나라도 있으면 정상적으로 행이 반환된다. 단, NULL 자체와 매칭되는 행은 여전히 찾을 수 없다.

#### 3. NULL과의 비교가 항상 UNKNOWN인 이유는?

NULL은 "값이 없음"이 아니라 **"알 수 없음(Unknown)"** 을 의미한다. 알 수 없는 값과의 어떤 비교도 결과를 확정할 수 없으므로 UNKNOWN을 반환한다.

- `NULL = NULL` → UNKNOWN (같은지 알 수 없음)
- `NULL != 5` → UNKNOWN (다른지도 알 수 없음)
- `NULL > 0` → UNKNOWN

NULL 여부를 확인하려면 반드시 `IS NULL` / `IS NOT NULL`을 사용해야 한다.

#### 4. 이 문제를 방지하는 패턴은?

**방법 1: WHERE절에서 NULL 제외 (이번 풀이에서 사용)**
```sql
WHERE ITEM_ID NOT IN (
    SELECT PARENT_ITEM_ID
    FROM ITEM_TREE
    WHERE PARENT_ITEM_ID IS NOT NULL
)
```

**방법 2: NOT EXISTS 사용 (NULL 영향 없음)**
```sql
WHERE NOT EXISTS (
    SELECT 1
    FROM ITEM_TREE T
    WHERE T.PARENT_ITEM_ID = I.ITEM_ID
)
```

**방법 3: LEFT JOIN + IS NULL**
```sql
FROM ITEM_INFO I
LEFT JOIN ITEM_TREE T ON I.ITEM_ID = T.PARENT_ITEM_ID
WHERE T.PARENT_ITEM_ID IS NULL
```

`NOT EXISTS`와 `LEFT JOIN` 방식은 NULL에 안전하므로, `NOT IN`보다 실무에서 더 권장된다.

### 실수했던 부분

**1. NOT IN 서브쿼리에서 NULL 미처리**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `NOT IN (SELECT PARENT_ITEM_ID FROM ITEM_TREE)` — NULL 포함으로 결과 0건 | `NOT IN (SELECT PARENT_ITEM_ID FROM ITEM_TREE WHERE PARENT_ITEM_ID IS NOT NULL)` |

## AI 코드 리뷰

### 개선할 점

1. **대안 고려**: `NOT IN`은 NULL 함정이 있으므로, 습관적으로 `NOT EXISTS`를 사용하면 이런 실수를 원천 차단할 수 있다. 성능 면에서도 대부분의 옵티마이저가 `NOT EXISTS`를 더 효율적으로 처리한다.

## 수정된 코드
```sql
SELECT I.ITEM_ID, I.ITEM_NAME, I.RARITY
FROM ITEM_INFO I
WHERE NOT EXISTS (
    SELECT 1
    FROM ITEM_TREE T
    WHERE T.PARENT_ITEM_ID = I.ITEM_ID
)
ORDER BY ITEM_ID DESC
```
