# FrontEnd 개발자 찾기

## 문제 요약
> DEVELOPERS 테이블에서 Front End 카테고리에 해당하는 스킬을 하나라도 보유한 개발자의 ID, 이메일, 이름, 성을 조회하는 문제. 비트 연산(&)을 활용하여 SKILL_CODE에 포함된 스킬을 판별해야 한다.

## 느낀점
>
- 풀긴 했지만 운좋게 아이디어가 떠오른 느낌이다.
- 실력으로 풀기 위해 여러 풀이 보면서 연습하자.

## 코드
```sql
SELECT ID, EMAIL, FIRST_NAME, LAST_NAME
FROM DEVELOPERS
WHERE SKILL_CODE & 
    (
        SELECT SUM(CODE)
        FROM SKILLCODES
        WHERE CATEGORY = 'Front End'
    ) > 0
ORDER BY ID
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

| 질문 | 답변 |
|------|------|
| 비트 연산으로 JOIN이 가능한가? | 가능하다. `ON d.SKILL_CODE & s.CODE > 0` 처럼 비트 AND 연산을 JOIN 조건으로 사용할 수 있다. |
| `&` 연산자의 의미 | 두 정수를 2진수로 비교하여 같은 위치의 비트가 모두 1인 경우에만 1을 반환. `A & B > 0`이면 A에 B 비트가 포함되어 있다는 뜻이다. |

### 실수했던 부분

**1. 불필요한 WITH, JOIN 사용**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `WITH` + `JOIN`을 사용하려 함 | 서브쿼리 하나로 Front End 코드 합산 후 `WHERE` 조건만으로 충분 |

**2. 불필요한 GROUP BY**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `GROUP BY CATEGORY` 추가 | 이미 `WHERE CATEGORY = 'Front End'`로 필터링했으므로 `SUM(CODE)`만 하면 됨 |

## AI 코드 리뷰

### 개선할 점

1. **현재 풀이는 깔끔하고 효율적**: 서브쿼리로 Front End 코드 합을 구한 뒤 비트 연산으로 필터링하는 접근은 간결하고 가독성이 좋다.

### 대안 풀이

**풀이 2: JOIN + DISTINCT 방식**
```sql
SELECT DISTINCT d.ID, d.EMAIL, d.FIRST_NAME, d.LAST_NAME
FROM DEVELOPERS d
JOIN SKILLCODES s ON d.SKILL_CODE & s.CODE > 0
WHERE s.CATEGORY = 'Front End'
ORDER BY d.ID
```
- SKILLCODES 테이블과 비트 연산 JOIN 후 Front End 카테고리만 필터링
- 한 개발자가 여러 Front End 스킬을 가질 수 있으므로 `DISTINCT` 필수
- JOIN의 동작 원리를 연습하기 좋은 풀이

**풀이 3: EXISTS 방식**
```sql
SELECT d.ID, d.EMAIL, d.FIRST_NAME, d.LAST_NAME
FROM DEVELOPERS d
WHERE EXISTS (
    SELECT 1
    FROM SKILLCODES s
    WHERE s.CATEGORY = 'Front End'
    AND d.SKILL_CODE & s.CODE > 0
)
ORDER BY d.ID
```
- 각 개발자마다 Front End 스킬이 하나라도 매칭되는지 확인
- `DISTINCT`가 필요 없어 중복 제거 비용이 없음
- "존재 여부"만 확인하면 되는 문제에 적합
