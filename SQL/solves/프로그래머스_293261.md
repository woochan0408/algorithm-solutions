# 물고기 종류 별 대어 찾기

## 문제 요약
> 물고기 종류별로 가장 큰 물고기의 ID, 이름, 길이를 조회하고 ID 오름차순 정렬

## 느낀점
>
- 

## 코드
```sql
SELECT FI.ID, FNI.FISH_NAME, FI.LENGTH
FROM FISH_INFO FI
JOIN FISH_NAME_INFO FNI ON FI.FISH_TYPE = FNI.FISH_TYPE
WHERE (FI.FISH_TYPE, FI.LENGTH) IN (SELECT FISH_TYPE, MAX(FI.LENGTH)
                    FROM FISH_INFO FI
                    GROUP BY FISH_TYPE
                    )
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

| 질문 | 답변 |
|------|------|
| `=` vs `IN` 차이 | 서브쿼리가 단일 행 반환하면 `=`, 여러 행 반환하면 `IN` 사용 |
| `IS` 용도 | `IS`는 NULL 비교 전용 (`IS NULL`, `IS NOT NULL`) |

### 실수했던 부분

**1. GROUP BY 규칙 위반**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| SELECT에 GROUP BY에 없는 컬럼 사용 | SELECT 컬럼은 GROUP BY에 있거나 집계 함수여야 함 |

**2. HAVING 절 오용**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `HAVING FI.LENGTH = MAX(FI.LENGTH)` | HAVING은 그룹 필터링용, 개별 행 매칭은 WHERE + 서브쿼리 |

**3. 여러 행 비교에 `=` 사용**

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `WHERE (col1, col2) = (서브쿼리)` | `WHERE (col1, col2) IN (서브쿼리)` |

## AI 코드 리뷰

### 개선할 점

1. **ORDER BY 누락**: 문제에서 ID 오름차순 정렬을 요구했으나 빠짐
2. **서브쿼리 별칭 중복**: 외부/내부 쿼리 모두 `FI` 사용 → 가독성 저하

## 수정된 코드
```sql
SELECT FI.ID, FNI.FISH_NAME, FI.LENGTH
FROM FISH_INFO FI
JOIN FISH_NAME_INFO FNI ON FI.FISH_TYPE = FNI.FISH_TYPE
WHERE (FI.FISH_TYPE, FI.LENGTH) IN (
    SELECT FISH_TYPE, MAX(LENGTH)
    FROM FISH_INFO
    GROUP BY FISH_TYPE
)
ORDER BY FI.ID
```
