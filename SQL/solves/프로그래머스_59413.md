# 입양 시각 구하기(2)

## 문제 요약
> 0시부터 23시까지 각 시간대별 입양 건수를 조회. 데이터에 없는 시간대도 0건으로 표시해야 함.

## 느낀점
>
- 갑자기 못 보던 개념을 한꺼번에 배웠다..
- 무조건 다시 풀어보기

## 코드
```sql
WITH RECURSIVE seq AS (
    SELECT 0 AS n
    UNION ALL
    SELECT n + 1 FROM seq
    WHERE n < 23
)
SELECT IFNULL(seq.n, 0) AS HOUR, COUNT(A.DATETIME) AS COUNT
FROM seq
LEFT JOIN ANIMAL_OUTS A ON seq.n = HOUR(A.DATETIME)
GROUP BY seq.n
ORDER BY HOUR
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

#### 1. 재귀 CTE로 연속 숫자 생성 (WITH RECURSIVE)

`WITH RECURSIVE cte AS (초기값 UNION ALL 재귀단계)` — 초기 행에서 출발해 조건을 만족할 때까지 행을 반복 생성.

```sql
WITH RECURSIVE seq AS (
    SELECT 0 AS n          -- 시작값
    UNION ALL
    SELECT n + 1 FROM seq
    WHERE n < 23           -- 종료 조건
)
SELECT n FROM seq;
-- 결과: 0, 1, 2, 3, ... , 23  (24행)
```

#### 2. SET 변수로 연속 숫자 생성 (@변수 + 서브쿼리)

`SET @var := 초기값` → 쿼리 안에서 `@var := @var + 1`로 행마다 값을 증가시켜 시퀀스 생성.

```sql
SET @n := -1;

SELECT @n := @n + 1 AS n
FROM information_schema.COLUMNS   -- 충분히 많은 행이 있는 아무 테이블
LIMIT 24;
-- 결과: 0, 1, 2, 3, ... , 23  (24행)
```

#### 3. LEFT JOIN에서 GROUP BY 대상을 잘못 잡으면 생기는 문제

LEFT JOIN의 목적은 왼쪽 테이블의 모든 행을 유지하는 것이다. 그런데 GROUP BY를 오른쪽 테이블 컬럼으로 하면 이 목적이 깨진다.

`HOUR(A.DATETIME)`은 오른쪽 테이블(ANIMAL_OUTS)의 컬럼이다. LEFT JOIN에서 매칭이 안 된 행은 `A.DATETIME`이 NULL → `HOUR(NULL)`도 NULL → GROUP BY가 NULL끼리 하나의 그룹으로 묶기 때문에, 기록 없는 시간대가 전부 NULL 그룹 하나로 합쳐져 사라진다. 왼쪽 테이블 컬럼(`seq.n`)으로 그룹핑해야 24행이 유지된다.

```sql
-- ❌ GROUP BY HOUR(A.DATETIME)  → NULL끼리 합쳐져 행 사라짐
-- ✅ GROUP BY seq.n             → 0~23 모두 유지
```

#### 4. LEFT JOIN에서 COUNT(*)와 COUNT(컬럼)의 차이

LEFT JOIN에서 매칭이 안 되면 오른쪽 컬럼이 전부 NULL인 행 1개가 생긴다. `COUNT(*)`는 이 행도 1로 세기 때문에 입양 0건인 시간도 1이 되어 버린다. `COUNT(컬럼)`은 NULL을 제외하므로 매칭 없는 시간대가 정확히 0이 된다.

```sql
-- ❌ COUNT(*)          → NULL 행도 1로 카운트
-- ✅ COUNT(A.DATETIME) → NULL 제외, 정확히 0
```

## AI 코드 리뷰

### 개선할 점

1. **불필요한 IFNULL 제거**: `seq.n`은 0~23으로 직접 생성한 값이라 절대 NULL이 될 수 없음. `IFNULL(seq.n, 0)`은 불필요한 래핑.
