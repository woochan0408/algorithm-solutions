# 백준 33943 🪙 간단한 동전 문제 (Hard) 파이썬

## 느낀점
>
- 언어 속도의 한계로 문제는 틀렸다.
- 근데 시간초과 해결을 위해 삽질하면서 많이 배웠다
- 배운 개념 자세히 읽어보기
- 문제는 좋아보인다.

## 흐름

1. M이 0이면 동전을 쓸 필요 없으므로 0 출력
2. N이 0이거나 0을 제거한 동전이 없으면 M을 만들 수 없으므로 -1 출력
3. BFS 탐색 범위(MAX) 계산: `max(|M|, 2000 × max(|P_i|))`
4. offset을 이용해 음수 합도 리스트 인덱스로 관리
5. BFS로 0에서 출발, 각 단계마다 모든 동전을 더해 새로운 합 탐색
6. M에 도달하면 해당 레벨(동전 개수) 출력, 도달 불가면 -1 출력

## 코드
```python
from collections import deque
import sys
input = sys.stdin.readline
N, M = map(int, input().split())
found = False
if(N != 0):
    arr = set(list(map(int, input().split()))) - {0}
if(M == 0):
    found = True
    print(0)
elif(N == 0):
    found = True
    print(-1)
elif(len(arr) == 0):
    found = True
    print(-1)
else:
    MAX = max(abs(M), 2000 * max(abs(i) for i in arr))
    offset = MAX
    
    # BFS 진행
    dq = deque(arr)
    visited = [False] * (2 * MAX + 1)
    
    for c in arr:
        visited[c + offset] = True
        
    # 탐색 전 기본값에 포함인지 확인
    if(visited[M + offset]):
        print(1)
        found = True
        
    level = 1
    while dq and not visited[M + offset]:
        for i in range(len(dq)):
            cur = dq.popleft()
            for dx in arr:
                n = cur + dx
                if(abs(n) > MAX):
                    continue
                if(visited[n + offset]):
                    continue
                dq.append(n)
                visited[n + offset] = True
        level += 1
        if(visited[M + offset]):
            found = True
            print(level)
            break
    if(not found):
        print(-1)
```

## 질문 & 실수 정리

### 새로 배운 것

#### BFS 탐색 범위 계산 (핵심)

이 문제는 음수 동전이 존재해서 BFS 상태 공간이 무한히 커질 수 있다. 단순히 "적당히 큰 범위"를 잡으면 안 되고, 최적 해의 동전 개수 K에 대한 수학적 상한이 필요하다.

**1단계: 최적 해의 동전 개수 K의 상한 구하기**

동전 2개 `{a, b}`로 목표 M을 만드는 문제는 `ax + by = M`을 푸는 것과 같다. 확장 유클리드 알고리즘으로 기본 해 `(x₀, y₀)`를 찾으면, 일반해는 `x = x₀ + bt`, `y = y₀ - at`이다. t를 조절하면 x를 `|b|` 미만으로, y를 `|a|` 미만으로 조정할 수 있으므로 `x + y < |a| + |b|`가 성립한다.

동전 가치 범위가 `-1000 ~ 1000`이므로: `K ≤ |a| + |b| ≤ 1000 + 1000 = 2000`

**동전이 3개 이상이면?**
동전이 많아질수록 목표에 도달하는 조합이 다양해져서 K는 줄어들면 줄었지 늘어나지 않는다. 3개의 동전이 있어도 **가장 유리한 2개만 골라서** M을 만들 수 있기 때문에, 2개일 때의 상한이 그대로 적용된다. 즉, 동전이 2개일 때가 "가장 비효율적으로 많이 움직여야 하는 최악의 상황"이다.

**2단계: 탐색 범위 계산**

K ≤ 2000이고, BFS에서 한 단계마다 합이 최대 `max(|P_i|) ≤ 1000`만큼 변하므로, 0에서 출발해서 중간에 갈 수 있는 합의 범위는:

`MAX = 2000 × max(|P_i|) ≤ 2,000,000`

이 범위 밖으로 나가는 상태는 최적 경로가 될 수 없으므로 무시해도 된다. 단, M 자체가 이 범위보다 클 수 있으므로 `MAX = max(|M|, 2000 × max(|P_i|))`로 설정한다.

- **핵심 원리**: 최적 해의 동전 개수 K에 상한이 있으므로, BFS 탐색 범위도 유한하게 제한된다
- **시간복잡도**: O(MAX × N), 최악 O(2,000,000 × 2,000)이지만 실제로는 동전 수가 많으면 K가 작아지고, K가 크면 동전 수가 적어서 관리 가능

#### offset을 이용한 음수 인덱스 처리

BFS에서 합이 음수가 될 수 있을 때, set 대신 리스트로 visited를 관리하려면 인덱스가 음수가 되는 문제가 생긴다. offset을 더해서 모든 인덱스를 양수로 변환하면 해결된다.

```python
MAX = 2_000_000
offset = MAX
visited = [False] * (2 * MAX + 1)  # 인덱스 0 ~ 4,000,000

# 합이 -2,000,000 → 인덱스 0
# 합이 0          → 인덱스 2,000,000
# 합이 2,000,000  → 인덱스 4,000,000
visited[n + offset] = True
```

- **핵심 원리**: 음수 범위를 양수 인덱스로 매핑하여 리스트 기반 O(1) 접근 가능

#### set보다 빠른 visited 체크: 리스트 사용

Python에서 `set`의 `in` 연산은 평균 O(1)이지만 해시 계산 + 충돌 처리 오버헤드가 있다. 반면 리스트의 인덱스 접근(`visited[i]`)은 단순 메모리 접근이라 훨씬 빠르다.

범위가 고정되어 있는 경우(이 문제처럼 합의 범위를 알 수 있을 때) 리스트를 사용하면 set 대비 상수 시간이 크게 줄어든다.

```python
# 느림: set 기반
visited = set()
if n in visited:  # 해시 계산 + 버킷 탐색

# 빠름: 리스트 기반
visited = [False] * size
if visited[n + offset]:  # 단순 메모리 접근
```

- **핵심 원리**: 범위가 정해져 있으면 리스트 인덱싱이 set의 해시 기반 접근보다 빠르다

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`MAX = abs(2000 * M)` — M 기반으로 범위 계산|`MAX = max(abs(M), 2000 * max(abs(i) for i in arr))` — 동전 가치 기반 계산|
|set으로 visited 관리 → 느림|리스트 + offset으로 visited 관리 → 빠름|
|초기 arr 값을 visited에 마킹 안 함 → 같은 값 재추가로 TLE|BFS 시작 전 arr의 모든 값을 visited에 표시|
|`visited[n + offset]` 접근 전 범위 체크 안 함 → 인덱스 에러 가능|`abs(n) > MAX` 체크를 visited 접근보다 먼저 수행|
|N=0일 때 arr 입력을 읽으려 함 → 에러|N=0이면 둘째 줄 입력이 없으므로 조건 분기 필요|
|모든 동전이 0인 경우 미처리|0 제거 후 arr가 비면 -1 출력|

## AI 코드 리뷰

### 개선할 점

1. **found 플래그 제거**: 현재 `found` 변수로 출력 여부를 관리하고 있는데, 함수로 감싸서 `return`으로 제어하면 플래그 없이 깔끔해진다.

2. **arr를 list로 변환**: BFS 내부에서 `for dx in arr`를 반복하는데, `arr`가 set이면 반복이 리스트보다 느리다. BFS 진입 전에 `list(arr)`로 변환해두는 것이 좋다.

3. **레벨 체크 위치 정리**: `M in visited` 체크와 `level` 증가가 while 루프 안팎에 분산되어 있다. 구조를 정리하면 가독성이 올라간다.

## 수정된 코드
```python
from collections import deque
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    
    if M == 0:
        print(0)
        return
    
    if N == 0:
        print(-1)
        return
    
    arr = list(set(map(int, input().split())) - {0})
    
    if not arr:
        print(-1)
        return
    
    MAX = max(abs(M), 2000 * max(abs(i) for i in arr))
    offset = MAX
    visited = [False] * (2 * MAX + 1)
    visited[0 + offset] = True
    
    dq = deque([0])
    level = 0
    
    while dq:
        level += 1
        for _ in range(len(dq)):
            cur = dq.popleft()
            for dx in arr:
                n = cur + dx
                if abs(n) > MAX:
                    continue
                if visited[n + offset]:
                    continue
                if n == M:
                    print(level)
                    return
                visited[n + offset] = True
                dq.append(n)
        
    print(-1)

solve()
```
