# 프로그래머스 1844 🎮 게임 맵 최단거리 파이썬

## 느낀점
>
- deque((0, 0)) 조심하자. 튜플 순서대로 값 꺼내서 넣는다고 인식함.
- 그냥 맘편이 deque() 선언 후 append 하자.
- AI리뷰 방식 처음본다. dp 활용같은데 좋은 아이디어같다.
(고딩 확통 길찾기처럼 1씩 써가는 방식인 듯 하다.)

## 흐름

1. 시작점 (0,0)에서 BFS 시작, level = 1 (시작 칸 포함)
2. 현재 level의 모든 노드를 꺼내서 상하좌우 탐색
3. 갈 수 있는 칸이면 큐에 추가하고 visited 처리
4. 목적지 (N-1, M-1) 도달 시 found = True → break
5. 한 레벨 처리 끝나면 level += 1
6. 도달 못하면 -1 리턴

## 코드
```python
"""
움직인 총 거리
"""
from collections import deque
def solution(maps):
    dq = deque([(0, 0)])
    N = len(maps)
    M = len(maps[0])
    level = 1
    visited = set([])
    visited.add((0, 0))
    found = False
    move = [[1, 0], [-1, 0], [0, 1], [0, -1]]
    
    while dq:
        for i in range(len(dq)):
            x, y = dq.popleft()
            for dx, dy in move:
                nx = x + dx
                ny = y + dy
                
                if(0 <= nx < N and 0 <= ny < M):
                    if(maps[nx][ny] != 0 and (nx, ny) not in visited):
                        dq.append((nx, ny))
                        visited.add((nx, ny))
                        if(nx == N-1 and ny == M-1):
                            found = True
                            break
        level += 1
        
        if(found):
            break
    
    if(found):
        answer = level
    else:
        answer = -1
    return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### deque 초기화 방식
`deque((0, 0))`으로 작성하면 튜플 `(0, 0)`이 iterable로 풀려서 `deque([0, 0])`이 된다. 좌표 튜플을 원소로 넣으려면 리스트로 감싸서 `deque([(0, 0)])`으로 작성하거나, 빈 deque를 만든 후 `dq.append((0, 0))`으로 추가해야 한다.
- **핵심 원리**: deque 생성자는 인자를 iterable로 해석하여 각 요소를 개별 원소로 추가함

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`deque((0, 0))` → `deque([0, 0])`이 됨|`deque([(0, 0)])` 또는 빈 deque 후 append|
|마지막 줄 `answer = 0`으로 결과 덮어씀|불필요한 `answer = 0` 제거|
|`found = True` 후 `break` 전에 `level += 1` 안 함|`level += 1`을 for 루프 뒤, found 체크 전으로 이동|

## AI 코드 리뷰

### 개선할 점

1. **visited 초기화 간소화**: `set([])` 후 `add`하는 대신 `{(0, 0)}`으로 한 번에 초기화할 수 있다.

2. **found 시 for i 루프 탈출 누락**: `found = True` 후 `break`가 내부 `for dx, dy` 루프만 탈출한다. `for i in range(len(dq))` 루프는 계속 돌아서 불필요한 노드 처리가 발생한다. found 체크를 for i 루프에도 추가하면 된다.

3. **거리 배열 방식 고려**: level 변수 + found 플래그 조합 대신, 2D 거리 배열을 사용하면 로직이 더 단순해진다. 각 칸에 도달 거리를 기록하면 별도의 visited set도 필요 없고, 목적지 도달 여부도 거리 배열만 확인하면 된다.

## 수정된 코드
```python
from collections import deque

def solution(maps):
    N = len(maps)
    M = len(maps[0])
    
    # 거리 배열: -1이면 미방문
    dist = [[-1] * M for _ in range(N)]
    dist[0][0] = 1
    
    dq = deque([(0, 0)])
    move = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    
    while dq:
        x, y = dq.popleft()
        
        for dx, dy in move:
            nx = x + dx
            ny = y + dy
            
            if (0 <= nx < N and 0 <= ny < M):
                if (maps[nx][ny] == 1 and dist[nx][ny] == -1):
                    dist[nx][ny] = dist[x][y] + 1
                    dq.append((nx, ny))
    
    return dist[N - 1][M - 1]
```
