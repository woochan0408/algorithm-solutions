# 백준 14867 🪣 물통 파이썬
## 느낀점
>
- 어우 새로운 인사이트를 주는 문제다
- grid나 그래프 형태가 아니어도 직접 추론해서 노선을 그리는 문제가 있구나~
- 물통에 물 붓는 계산하는데 너무 오래걸림.. 단순하게 생각하자.

## 흐름
- 상태를 `(x, y)` = (A에 담긴 물의 양, B에 담긴 물의 양)으로 두고, 시작 `(0, 0)`에서 목표 `(c, d)`까지 **최소 작업 횟수**를 구한다.
- 한 번의 작업(F/E/M)은 상태를 다른 상태로 바꾸는 “간선 1개”이므로, 전체를 **최단거리 탐색**으로 본다.
- 이 문제에서 중요한 관찰: Fill/Empty/Move 연산의 결과는 항상 **둘 중 하나의 물통이 비어있거나(0) 가득 차게(용량)** 되므로, 실제로 탐색되는 상태 수가 최대 `2(a+1) + 2(b+1)` 정도로 제한된다.
- 따라서 방문 체크를 하며 상태들을 레벨(거리) 순으로 확장하면 최소 횟수를 구할 수 있다.

## 코드
```python
from collections import deque

a, b, c, d = map(int, input().split())

dq = deque()
dq.append((0, 0))
visited = set()
visited.add((0, 0))
level = 0
result = -1
while dq:
    if (c, d) in visited:
        result = level
        break

    level += 1
    for _ in range(len(dq)):
        x, y = dq.popleft()

        # x -> y
        if x + y > b:
            nx = x + y - b
            ny = b
        else:
            nx = 0
            ny = x + y
        if (nx, ny) not in visited:
            visited.add((nx, ny))
            dq.append((nx, ny))

        # y -> x
        if x + y > a:
            nx = a
            ny = x + y - a
        else:
            nx = x + y
            ny = 0
        if (nx, ny) not in visited:
            visited.add((nx, ny))
            dq.append((nx, ny))

        # Fill
        nx, ny = a, y
        if (nx, ny) not in visited:
            visited.add((nx, ny))
            dq.append((nx, ny))

        nx, ny = x, b
        if (nx, ny) not in visited:
            visited.add((nx, ny))
            dq.append((nx, ny))

        # Empty
        nx, ny = 0, y
        if (nx, ny) not in visited:
            visited.add((nx, ny))
            dq.append((nx, ny))

        nx, ny = x, 0
        if (nx, ny) not in visited:
            visited.add((nx, ny))
            dq.append((nx, ny))

print(result)
```

## 질문 & 실수 정리

### 새로 배운 것

#### 상태 그래프 최단거리로 보기
물통의 상태 `(x, y)`를 노드로 두고, 가능한 연산(F/E/M)을 간선으로 보면 “최소 작업 수”는 최단거리 문제가 된다.
- **핵심 원리**: 모든 간선의 비용이 1이므로 레벨 순으로 확장하는 탐색이 최소 연산을 보장한다.
- **시간복잡도**: `O(방문 상태 수)`.

#### 경계 상태만 등장하는 관찰
Fill/Empty는 한 물통을 **항상 0 또는 용량**으로 만들고, Move는 “source가 비거나(dest가 가득 참)” 둘 중 하나가 반드시 발생한다.
- **핵심 원리**: 그래서 매 연산 후 상태는 최소 한 물통이 `{0, capacity}`에 속한다.
- **시간복잡도 영향**: 방문 가능한 상태 수가 대략 `O(a+b)`로 줄어, 제약이 커도 탐색이 가능해진다.

#### BFS 거리(레벨) 관리
`level`을 외부에서 돌리는 방식도 가능하지만, 일반적으로는 큐에 `(상태, 거리)`를 함께 넣는 쪽이 실수(오프바이원)를 줄인다.
- **핵심 원리**: pop한 상태의 `dist`가 곧 그 상태까지의 최소 작업 횟수.

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|레벨을 while 진입 시점에 올려서 시작 상태가 1로 잡히는 구조(초안)|거리 0인 시작 상태를 기준으로, 레벨 증가 타이밍을 정확히 맞추거나 `(state, dist)`로 관리|
|Empty 연산(E(A), E(B)) 누락(초안)|문제의 6가지 연산(F2/E2/M2)을 빠짐없이 모두 고려|
|디버그용 출력 유지(초안)|제출 전 제거(상태 수가 커지면 시간 초과 위험)|

## AI 코드 리뷰

### 개선할 점

1. **거리 관리 단순화**: `level`을 별도로 굴리는 대신, 큐에 `(x, y, dist)`를 넣으면 오프바이원 실수를 줄이고 목표 도달 즉시 종료할 수 있다.
2. **중복 로직 제거**: “붓기” 연산(M)을 함수로 분리하면 (A→B, B→A) 코드가 짧아지고 실수 가능성이 줄어든다.
3. **visited 최적화**: `(x, y)` 튜플 set도 충분히 통과 가능하지만, `x*(b+1)+y`로 인코딩하면 파이썬에서 조금 더 빠르고 메모리도 덜 쓴다.
4. **목표 체크 위치**: `visited` 포함 여부를 라운드 시작에 확인하는 대신, pop 시점에 `if (x,y)==(c,d)`로 체크하면 흐름이 직관적이다.

## 수정된 코드
```python
import sys
from collections import deque

input = sys.stdin.readline

a, b, c, d = map(int, input().split())

def pour(x, y, cap_y):
    # x -> y
    move = min(x, cap_y - y)
    return x - move, y + move

def encode(x, y):
    return x * (b + 1) + y

dq = deque([(0, 0, 0)])  # (x, y, dist)
visited = {encode(0, 0)}

while dq:
    x, y, dist = dq.popleft()

    if x == c and y == d:
        print(dist)
        break

    # 다음 후보 상태 6개
    candidates = [
        (a, y),          # F(A)
        (x, b),          # F(B)
        (0, y),          # E(A)
        (x, 0),          # E(B)
        pour(x, y, b),   # M(A,B)
    ]

    # M(B,A): swap해서 붓고 다시 원복
    ny, nx = pour(y, x, a)
    candidates.append((nx, ny))

    for nx, ny in candidates:
        key = encode(nx, ny)
        if key not in visited:
            visited.add(key)
            dq.append((nx, ny, dist + 1))
else:
    print(-1)
```
