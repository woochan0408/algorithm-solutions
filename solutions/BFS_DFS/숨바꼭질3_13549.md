## 느낀점
>
- 실수가 왤캐 많았니..
- if문 연산자 우선순위 조심
- 기중치 2개인 경우 0-1 BFS로 간단한 구현 가능
- 아이디어 챙기고 코드정리 하자.

## 흐름

1. 목표 지점(K)에서 시작하여 역방향 BFS 탐색
2. 세 가지 이동: `÷2`(0초), `+1`(1초), `-1`(1초)
3. 0-1 BFS로 비용 0은 `appendleft`, 비용 1은 `append`
4. 시작점(N)에 도달하면 최소 시간 출력

## 코드

```python
from collections import deque
N, M = map(int, input().split())
dq = deque([(M, 0)])
# 같은 곳 또 visited 하더라도 최소시간이 다르면 다른 것임
# 즉, dictionary로 관리하면서 갱신.
visited = {M : 0}
while dq:
    x, time = dq.popleft()
    
    if(x == N):
        # 결과출력
        print(time)
        break
    # 나누기 이동 가능?
    if(x != 0 and x%2 == 0):
        nextX = x//2
        nextTime = time
        if(nextX not in visited or visited[nextX] > nextTime):
            visited[nextX] = nextTime
            dq.appendleft((nextX, nextTime))
    # +1 이동 가능?
    nextX = x+1
    nextTime = time+1
    if(nextX <= 100000 and (nextX not in visited or visited[nextX] > nextTime)):
        visited[nextX] = nextTime
        dq.append((nextX, nextTime))
    # -1 이동가능?
    nextX = x-1
    nextTime = time+1
    if(nextX >= 0 and (nextX not in visited or visited[nextX] > nextTime)):
        visited[nextX] = nextTime
        dq.append((nextX, nextTime))
```

## 질문 & 실수 정리

### 0-1 BFS란?

일반 BFS는 모든 간선의 가중치가 동일할 때 최단 경로를 보장한다. 하지만 이 문제처럼 **가중치가 0과 1 두 종류**만 있는 경우, deque의 양방향 추가를 활용해 최단 경로를 구할 수 있다.

**핵심 원리**: 비용이 작은 것을 항상 먼저 처리하면 된다.

- **비용 0인 이동** → `appendleft()` (앞에 추가, 바로 다음에 처리)
- **비용 1인 이동** → `append()` (뒤에 추가, 나중에 처리)

이렇게 하면 별도의 "레벨 관리" 없이도 자연스럽게 비용 순서대로 탐색하게 된다.

**시간복잡도**: O(V + E)로 일반 BFS와 동일

### continue의 스코프 문제

`continue`는 **while/for 루프 전체**를 건너뛴다. if문만 빠져나오는 게 아니다.

```python
# 잘못된 코드: 나누기 스킵하면 +1, -1도 스킵됨
if(x != 0 and x%2 == 0):
    if(조건):
        continue  # ← while 루프의 다음 반복으로!
# +1 이동 (실행 안 됨!)
# -1 이동 (실행 안 됨!)
```

**해결책**: 조건을 뒤집어서 처리

```python
# 올바른 코드
if(x != 0 and x%2 == 0):
    if(nextX not in visited or visited[nextX] > nextTime):
        # 조건 만족할 때만 실행
        visited[nextX] = nextTime
        dq.appendleft((nextX, nextTime))
# +1 이동 (정상 실행)
# -1 이동 (정상 실행)
```

### 연산자 우선순위: and > or

`and`가 `or`보다 우선순위가 높다. 괄호 없이 혼용하면 의도와 다르게 해석된다.

```python
# 의도: (범위 내) AND (미방문 OR 더 좋은 비용)
if nextX <= 100000 and nextX not in visited or visited[nextX] > nextTime:
    
# 실제 해석: ((범위 내) AND (미방문)) OR (더 좋은 비용)
if (nextX <= 100000 and nextX not in visited) or visited[nextX] > nextTime:
```

이 경우 `nextX not in visited`여도 `or` 뒤의 `visited[nextX]`가 평가될 수 있다 → **KeyError!**

**해결책**: 괄호로 의도를 명확히

```python
if nextX <= 100000 and (nextX not in visited or visited[nextX] > nextTime):
```

### 시작점 visited 초기화

시작점을 큐에 넣을 때 visited도 함께 초기화해야 한다.

```python
# 잘못된 코드
dq = deque([(M, 0)])
visited = {}  # M이 없음!

# 올바른 코드
dq = deque([(M, 0)])
visited = {M: 0}  # 시작점 포함
```

## AI 코드 리뷰

### 개선할 점

1. **변수명 컨벤션**: 문제에서 시작점이 `N`, 목표점이 `K`인데, 코드에서는 `N, M`으로 받아 혼란스럽다. `N, K` 또는 `start, target`으로 변경 권장

2. **중복 코드 정리**: 세 가지 이동의 패턴(범위 체크 + visited 체크 + 큐 추가)이 비슷하므로 헬퍼 함수로 분리하면 가독성 향상

## 수정된 코드

```python
from collections import deque

def solve():
    N, K = map(int, input().split())
    
    if N == K:
        print(0)
        return
    
    dq = deque([(K, 0)])
    visited = {K: 0}
    
    def try_move(next_x, next_time, front=False):
        """이동 시도. front=True면 appendleft"""
        if 0 <= next_x <= 100000:
            if next_x not in visited or visited[next_x] > next_time:
                visited[next_x] = next_time
                if front:
                    dq.appendleft((next_x, next_time))
                else:
                    dq.append((next_x, next_time))
    
    while dq:
        x, time = dq.popleft()
        
        if x == N:
            print(time)
            return
        
        # 나누기 이동 (0초) - 짝수일 때만
        if x != 0 and x % 2 == 0:
            try_move(x // 2, time, front=True)
        
        # +1, -1 이동 (1초)
        try_move(x + 1, time + 1)
        try_move(x - 1, time + 1)

solve()
```
