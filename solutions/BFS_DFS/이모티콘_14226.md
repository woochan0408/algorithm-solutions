## 느낀점
>
- 아침에 머리가 잘 돌아가서 실수없이 잘 풀었다.
- BFS의 시간복잡도는 상태의 상한선(하한선)과 밀접한 관계에 있다
(잘 선택하는게 정말 중요)
- 시작점 방문 꼭 체크하자. 
(200만번째 실수 중)
- `그리디 -> DP -> BFS` 순 알고리즘 떠올리기 내가 만들었지만 참 잘 만들었다.
- DP 가능성 판단은 **양방향 여부**가 결정한다.
(개념정리 참고)

## 흐름

1. 상태를 (화면 이모티콘 수, 클립보드 이모티콘 수)로 정의
2. 3가지 연산(복사, 붙여넣기, 삭제)을 간선으로 보고 BFS 탐색
3. `visited[화면][클립보드]`로 중복 방문 방지
4. level-wise BFS로 최소 시간(레벨) 계산
5. 화면 이모티콘 수가 N에 도달하면 현재 레벨 출력

## 코드

```python
from collections import deque
N = int(input())
visited = [[False]*2*N for i in range(2*N)]
dq = deque()
dq.append((1, 0))
level = 0
while dq:
    level += 1
    for i in range(len(dq)):
        num, state = dq.popleft()
        # 복사하거나 : 작은 값을 복사할 이유가 있을수도
        if(not visited[num][num]):
            visited[num][num] = True
            dq.append((num, num))
        # 붙여넣거나.
        if(num+state < 2*N and not visited[num + state][state]):
            visited[num + state][state] = True
            dq.append((num + state, state))
        # 빼거나
        if(num-1 >= 0 and not visited[num-1][state]):
            visited[num-1][state] = True
            dq.append((num-1, state))
    if(True in visited[N]):
        print(level)
        break
```

## 질문 & 실수 정리

### 새로 배운 것

#### 알고리즘 선택 과정: 그리디 → DP → BFS

이 문제는 "최소 시간(연산 횟수)"을 구하는 최적화 문제다.

**1. 그리디 검토**
매 단계에서 "최대한 복사해서 붙여넣기"하면 최적일 것 같지만, 복사 타이밍에 따라 결과가 완전히 달라진다. S=18일 때, 단순 그리디로는 어떤 시점에 복사하고 어떤 시점에 삭제할지 판단 기준이 없다. 그리디가 성립하려면 "지금 가장 좋아 보이는 선택이 전체 최적을 보장"해야 하는데, 이 문제에선 성립하지 않는다.

**2. DP 검토**
상태를 `dp[화면][클립보드] = 최소 시간`으로 정의할 수 있다. 하지만 삭제 연산 때문에 화면 값이 줄어들 수 있어서 전이 방향이 양방향이다. 일반적인 for문 순회로는 갱신 순서를 보장할 수 없다.

**3. BFS 선택**
모든 연산의 비용이 1초로 동일하므로, 가중치가 모두 1인 최단 경로 문제가 된다. 양방향 전이가 있어도 BFS는 최단 거리를 보장하므로 가장 자연스러운 선택이다.
- **핵심 원리**: 상태 (화면, 클립보드)를 노드로, 3가지 연산을 간선으로 모델링한 BFS
- **시간복잡도**: O(S²) — 상태 수가 최대 S × S

#### BFS 탐색 범위 상한: 2*S

배열 크기를 `2*S`로 잡는 근거는 다음과 같다.

- **화면 값이 S를 넘으면** S에 도달하려면 삭제를 반복해야 한다.
- **화면 값이 2*S 이상이면** 최소 S번 삭제가 필요한데, S번의 연산이면 1에서 시작해도 훨씬 효율적인 경로가 존재한다.
- **따라서** `2*S` 이상은 최적 경로에 포함될 수 없으므로 탐색할 필요가 없다.
- **클립보드**는 화면 값을 복사한 것이므로 클립보드 ≤ 화면 < `2*S` 범위 안에 자연스럽게 들어간다.

#### BFS 시간복잡도 계산법

BFS의 시간복잡도는 **방문 가능한 상태 수(V) + 간선 수(E)**로 결정된다.

- **상태 수(V)**: visited 배열의 크기가 곧 최대 상태 수다. 이 문제에서는 `(화면, 클립보드)` 2차원이고 각각 0 ~ 2N-1 범위이므로 V = 2N × 2N = 4N²
- **간선 수(E)**: 각 상태에서 연산이 3개(복사, 붙여넣기, 삭제)로 고정이므로 E = 3V = 12N²
- **결과**: O(V + E) = O(N²)

범위를 `3N`으로 잡으면 V = 9N²이 되어 상수가 커진다. 범위를 타이트하게 잡을수록 실행 시간에 유리하다.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| 시작 상태 `(1, 0)`을 큐에 넣으면서 `visited[1][0] = True` 미설정 | 큐에 삽입하는 시점에 반드시 visited 마킹 (BFS 원칙) |

## AI 코드 리뷰

### 개선할 점

1. **변수명 개선**: `num`과 `state`는 의미가 모호하다. `screen`과 `clipboard`로 바꾸면 문제 맥락과 일치해서 코드만 봐도 역할이 명확해진다.
2. **시작 상태 visited 미설정**: `(1, 0)`을 큐에 넣으면서 `visited[1][0] = True`를 설정하지 않았다. 다른 경로에서 (1,0)에 다시 도달하면 중복으로 큐에 들어갈 수 있다. BFS의 원칙은 "삽입 시점에 visited 마킹"이다.
3. **종료 조건 비효율**: `True in visited[N]`은 매 레벨마다 O(N) 선형 탐색을 한다. 삽입 시점에 `screen == N` 또는 `screen + clipboard == N`을 체크하면 O(1)로 즉시 종료 가능하다.
4. **루프 변수**: 사용하지 않는 `i`는 `_`로 변경.

## 수정된 코드

```python
from collections import deque

S = int(input())
visited = [[False] * (2 * S) for _ in range(2 * S)]
dq = deque()
dq.append((1, 0, 0))  # (screen, clipboard, time)
visited[1][0] = True

while dq:
    screen, clipboard, time = dq.popleft()

    # 복사: 화면 값을 클립보드에 저장
    if not visited[screen][screen]:
        visited[screen][screen] = True
        dq.append((screen, screen, time + 1))

    # 붙여넣기: 클립보드 값을 화면에 추가
    next_screen = screen + clipboard
    if clipboard > 0 and next_screen < 2 * S and not visited[next_screen][clipboard]:
        if next_screen == S:
            print(time + 1)
            break
        visited[next_screen][clipboard] = True
        dq.append((next_screen, clipboard, time + 1))

    # 삭제: 화면에서 하나 제거
    if screen - 1 >= 0 and not visited[screen - 1][clipboard]:
        if screen - 1 == S:
            print(time + 1)
            break
        visited[screen - 1][clipboard] = True
        dq.append((screen - 1, clipboard, time + 1))
