# 백준 1300 🔢 K번째 수 파이썬

## 느낀점
>
- 아이디어가 참 좋다
- 이런 문제 볼때마다 문제 만든이에 대한 경외감이 든다.

## 흐름

1. N×N 배열에서 A[i][j] = i×j이고, 이를 정렬했을 때 k번째 수를 찾는 문제
2. 배열을 실제로 만들면 N²개 (최대 10¹⁰개)라 불가능
3. **값에 대한 이분탐색**: "x 이하인 수가 k개 이상인 최소의 x"를 탐색
4. i번째 행 `[i, 2i, 3i, ..., Ni]`에서 x 이하인 개수 = `min(x // i, N)`
5. 모든 행에 대해 합산하여 총 개수 계산 → O(N)
6. 이분탐색으로 조건 만족하는 최솟값 탐색 → O(N log N²)

## 코드

```python
N = int(input())
K = int(input())
l = 0
r = N ** 2
ans = float("inf")
while l <= r:
    mid = (l+r) // 2
    hap = 0
    for i in range(1, N+1):
        hap += min(mid // i, N)
    if(hap >= K):
        ans = min(ans, mid)
        r = mid - 1
    elif(hap < K):
        l = mid + 1
print(ans)
```

## 질문 & 실수 정리

### 새로 배운 것

#### Parametric Search (값에 대한 이분탐색)
일반적인 이분탐색은 정렬된 배열에서 인덱스를 탐색하지만, Parametric Search는 **"값 자체"를 탐색 범위로 설정**한다. "이 값이 조건을 만족하는가?"를 판별 함수로 검사하며 범위를 좁혀간다.
- **핵심 원리**: 결정 문제로 변환 → "x가 답이 될 수 있는가?"를 O(N) 등으로 검증
- **시간복잡도**: O(N × log(탐색범위))

#### 이분탐색 조건 선택 기준
탐색 목적에 따라 조건문이 달라진다.
- **정확한 값 찾기**: `== target` → break
- **조건 만족 최솟값 (lower bound)**: `>= target` → 만족하면 왼쪽 탐색
- **조건 만족 최댓값 (upper bound)**: `<= target` → 만족하면 오른쪽 탐색

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `r = N ** N` (N의 N제곱) | `r = N ** 2` (N의 제곱) |
| `mid // 2` (고정값으로 나눔) | `mid // i` (행 번호로 나눔) |
| `hap == K`일 때만 갱신 | `hap >= K`일 때 갱신 (정확히 K개인 값이 없을 수 있음) |
| `r -= 1` | `r = mid - 1` |
| `print(ans + 1)` | `print(ans)` (찾은 값 자체가 답) |

## AI 코드 리뷰

### 개선할 점

1. **변수명**: `hap`보다 `count`가 "x 이하인 수의 개수"라는 의미를 더 명확히 전달
2. **시작값**: `l = 0`이지만 배열에 0은 없으므로 `l = 1`로 시작해도 무방
3. **ans 갱신 패턴**: `ans = float("inf")` + `min()` 방식 대신, 이분탐색 종료 후 `l`이 답이 되는 패턴이 더 간결함

## 수정된 코드

```python
import sys
input = sys.stdin.readline

N = int(input())
K = int(input())

l, r = 1, N * N

while l < r:
    mid = (l + r) // 2
    count = 0
    for i in range(1, N + 1):
        count += min(mid // i, N)
    
    if count >= K:
        r = mid
    else:
        l = mid + 1

print(l)
```
