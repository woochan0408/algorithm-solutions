# 백준 2512 💰 예산 파이썬

## 느낀점
>
- 문제를 잘못 이해해서 범위를 너무 넓게 잡았다.

## 흐름

1. 상한액을 이분탐색으로 결정한다.
2. 탐색 범위: `l = 1`, `r = max(arr)` (상한액은 최대 요청액을 초과할 수 없음)
3. `mid`를 상한액으로 설정하고, 각 지방에 `min(요청액, mid)`를 배정하여 총합 계산
4. 총합이 M 이하이면 상한액을 더 올려보고 (`l = mid + 1`), 초과하면 낮춘다 (`r = mid - 1`)
5. 조건을 만족하는 최대 `mid`를 출력

## 코드
```python
import sys
input = sys.stdin.readline

N = int(input())
arr = list(map(int, input().split()))
M = int(input())

l = 1
r = M+1
ans = 0
while l <= r:
    mid = (l+r) // 2
    # 예산 계산
    hap = 0
    for cur in arr:
        hap += cur if cur <= mid else mid

    # 예산 초과
    if(hap > M):
        r = mid - 1

    # 예산 적절
    else:
        ans = max(ans, mid)
        l = mid + 1

if(ans == M+1):
    print(max(arr))
else:
    print(ans)
```

## 질문 & 실수 정리

### 새로 배운 것

#### 매개변수 탐색 (Parametric Search)
최적화 문제를 결정 문제로 변환하는 기법. "최대 상한액은 얼마인가?"라는 최적화 문제를 "상한액이 X일 때, 총 예산이 M 이하인가?"라는 결정 문제로 바꿔서 이분탐색으로 풀 수 있다.
- **핵심 원리**: 답이 될 수 있는 값의 범위에서 이분탐색을 수행하며, 조건 함수의 결과가 단조성(monotonic)을 가질 때 적용 가능
- **시간복잡도**: O(N log K) — N은 배열 크기, K는 탐색 범위

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`r = M+1`로 불필요하게 넓은 탐색 범위 설정|`r = max(arr)` — 상한액은 최대 요청액을 초과할 수 없음|
|`ans = max(ans, mid)`로 불필요한 비교|`ans = mid` — l이 증가하므로 mid는 항상 이전 ans 이상|

## AI 코드 리뷰

### 개선할 점

1. **탐색 범위 최적화**: `r = M+1`은 M이 최대 10억이므로 약 30번의 탐색이 필요하지만, `r = max(arr)`로 설정하면 최대 100,000까지만 탐색하므로 약 17번으로 줄어든다. 또한 `ans == M+1` 예외 처리가 불필요해진다.
2. **ans 갱신 단순화**: 이분탐색에서 `l`이 계속 증가하므로 `else` 분기에서의 `mid`는 항상 이전 `ans` 이상이다. `ans = mid`로 충분하다.
3. **변수명 개선**: `hap` → `total`, `arr` → `budgets`로 변경하면 코드의 의도가 더 명확해진다.

## 수정된 코드
```python
import sys
input = sys.stdin.readline

N = int(input())
budgets = list(map(int, input().split()))
M = int(input())

l = 1
r = max(budgets)
ans = 0

while l <= r:
    mid = (l + r) // 2
    total = 0
    for cur in budgets:
        total += cur if cur <= mid else mid

    if total > M:
        r = mid - 1
    else:
        ans = mid
        l = mid + 1

print(ans)
```
