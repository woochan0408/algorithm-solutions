# 프로그래머스 87946 🏰 피로도 파이썬

## 느낀점
>
- 새로운 아이디어를 배웠다.
- 꼭 다시풀자.

## 흐름

1. 던전을 방문하는 모든 순서를 탐색해야 하므로 DFS + 백트래킹 사용
2. 방문 상태를 비트마스크로 표현하여 메모이제이션 적용
3. `(현재 피로도, 방문 비트마스크)` 상태에서 앞으로 더 탐험 가능한 최대 던전 수를 리턴
4. 각 던전에 대해 "방문하지 않았고 + 최소 피로도 이상"이면 재귀 탐색
5. 모든 경우의 최댓값을 메모에 저장하고 반환

## 코드
```python
def solution(k, dungeons):
    N = len(dungeons)
    memo = {}
    
    def dfs(k, visited):
        if (k, visited) in memo:
            return memo[(k, visited)]
        
        best = 0
        for i in range(N):
            if not (visited & (1 << i)) and k >= dungeons[i][0]:
                best = max(best, 1 + dfs(k - dungeons[i][1], visited | (1 << i)))
        
        memo[(k, visited)] = best
        return best
    
    return dfs(k, 0)
```

## 질문 & 실수 정리

### 새로 배운 것

#### 비트마스크를 활용한 방문 상태 표현
집합(set) 대신 정수의 비트로 방문 여부를 표현하면, 해시 가능한 상태로 만들 수 있어 메모이제이션 키로 바로 사용할 수 있다.
- **핵심 원리**: i번째 원소의 방문 여부를 `visited & (1 << i)`로 확인하고, `visited | (1 << i)`로 방문 처리. 원본 값을 변경하지 않으므로 자연스럽게 백트래킹이 된다.

#### 메모이제이션의 상태 정의
메모이제이션에서 가장 중요한 것은 "같은 결과를 보장하는 상태"를 올바르게 정의하는 것이다. 이 문제에서는 `(남은 피로도, 방문한 던전 집합)`이 같으면 앞으로의 최적 결과도 동일하다.
- **핵심 원리**: 상태 = 현재 결정에 영향을 주는 모든 정보. 리턴값 = 해당 상태에서의 최적해.

#### 전역 visited vs 파라미터 visited
전역 `set`으로 visited를 관리하면 직접 `add`/`remove`로 원복하는 백트래킹이 필요하다. 이 방식은 순수 완전탐색에서는 동작하지만, 메모이제이션과 함께 쓰기 어렵다. 반면 비트마스크를 파라미터로 넘기면 `visited | (1 << i)`가 새 값을 생성하므로 원본이 불변하여 자동 백트래킹이 되고, 그 자체로 메모 키가 된다.
- **핵심 원리**: 메모이제이션을 쓸 때는 상태를 불변 파라미터로 넘기는 것이 안전하고 깔끔하다. 전역 가변 상태는 캐시 적중 시 상태 불일치 위험이 있다.

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`visited`를 `set`으로 사용 → 메모 키로 활용 어려움|비트마스크(정수)로 표현하여 바로 메모 키로 사용|
|for문 안에서 바로 `return` → 첫 번째 경우만 탐색|`max`로 모든 경우를 비교하여 최댓값 산출|
|백트래킹 누락 (visited 복원 안 함)|비트 연산 `visited \| (1 << i)`는 원본 불변 → 자동 백트래킹|
|`dfs(k, n)` 정의인데 `dfs(k+1)`로 호출|`dfs(k - dungeons[i][1], visited \| (1 << i))`로 올바른 인자 전달|

## AI 코드 리뷰

### 개선할 점

1. **던전 데이터 언패킹**: `dungeons[i][0]`, `dungeons[i][1]` 대신 구조 분해를 사용하면 의미가 명확해진다.
2. **변수명 명확화**: `best` → `max_explore`로 변경하면 "앞으로 더 탐험 가능한 최대 수"라는 의미가 드러난다.
3. **lru_cache 활용 가능**: `functools.lru_cache`를 쓰면 memo 딕셔너리를 직접 관리할 필요가 없다. 단, 이 문제에서는 직접 구현한 방식도 충분히 깔끔하다.

## 수정된 코드
```python
def solution(k, dungeons):
    N = len(dungeons)
    memo = {}
    
    def dfs(fatigue, visited):
        if (fatigue, visited) in memo:
            return memo[(fatigue, visited)]
        
        max_explore = 0
        for i in range(N):
            min_req, cost = dungeons[i]
            if not (visited & (1 << i)) and fatigue >= min_req:
                max_explore = max(max_explore, 1 + dfs(fatigue - cost, visited | (1 << i)))
        
        memo[(fatigue, visited)] = max_explore
        return max_explore
    
    return dfs(k, 0)
```
