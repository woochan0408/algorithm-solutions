## 느낀점

- 문제를 지맘대로 해석했다.
   - row, col 순서가 아닌 col, row 순서로 제공
   - (0, 0)이 아닌, (1, 1)에서부터 시작
   - 이동방향은 2개 (아래, 오른쪽)으로 제한
- 잘못 해석한 문제의 답안도 찾아봤다

## 흐름

1. 격자를 (0,0)에서 (N-1, M-1)까지의 2차원 좌표로 변환
2. puddles 좌표를 (col, row) 1-indexed → (row-1, col-1) 0-indexed로 변환하여 wall set에 저장
3. Top-down DP로 `td(x, y)` = (0,0)에서 (x, y)까지 도달하는 최단경로 수 정의
4. 오른쪽/아래로만 이동 가능하므로, (x, y)에 올 수 있는 이전 칸은 (x-1, y)와 (x, y-1)
5. 웅덩이면 0 반환, (0,0)이면 1 반환, 나머지는 위쪽 + 왼쪽 결과 합산
6. 결과를 1,000,000,007로 나눈 나머지 반환

## 코드
```python
import sys
sys.setrecursionlimit(10**6)
def solution(m, n, puddles):
    move = [[-1, 0], [0, -1]]
    N = n
    M = m
    wall = set()
    memo = {}
    for c, r in puddles:
        
        wall.add((r-1, c-1))
        
    def td(x, y):
        if((x, y) in wall):
            return 0
        if(x == 0 and y == 0):
            return 1
        if((x, y) in memo):
            return memo[(x, y)]
        
        result = 0
        for dx, dy in move:
            nx = x + dx
            ny = y + dy
            if(0 <= nx < N) and (0 <= ny < M):
                result += td(nx, ny)
        memo[(x, y)] = result%1000000007
        return result
    
    return td(N-1, M-1)%1000000007
```

## 변형문항

### 4방향 이동 가능 시 BFS로 최단경로 개수 구하기
만약 이 문제에서 상하좌우 모든 방향 이동이 가능하다면, DP로는 풀 수 없다. 순환이 발생할 수 있어 이전 상태가 명확하지 않기 때문이다. 이 경우 BFS를 사용하여 각 칸까지의 최단거리(`dist`)와 최단경로 수(`count`)를 동시에 관리한다. 인접 칸에 대해 더 짧은 경로를 발견하면 갱신하고, 같은 최단거리면 경로 수를 누적한다.
- **핵심 원리**: `dist` + `count` 두 배열만으로 경로 자체를 저장하지 않고 경로 수를 셀 수 있음
- **시간복잡도**: O(N × M)

```python
from collections import deque

def bfs_shortest_paths(n, m, puddles):
    """4방향 이동 가능 시 최단경로 개수 (BFS)"""
    MOD = 1_000_000_007
    INF = float('inf')
    wall = set()
    for c, r in puddles:
        wall.add((r - 1, c - 1))

    dist = [[INF] * m for _ in range(n)]
    count = [[0] * m for _ in range(n)]

    dist[0][0] = 0
    count[0][0] = 1
    queue = deque([(0, 0)])

    while queue:
        x, y = queue.popleft()
        for dx, dy in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m and (nx, ny) not in wall:
                if dist[nx][ny] > dist[x][y] + 1:
                    dist[nx][ny] = dist[x][y] + 1
                    count[nx][ny] = count[x][y]
                    queue.append((nx, ny))
                elif dist[nx][ny] == dist[x][y] + 1:
                    count[nx][ny] = (count[nx][ny] + count[x][y]) % MOD

    return count[n - 1][m - 1] % MOD
```

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| move에 4방향 `[[-1,0],[1,0],[0,-1],[0,1]]` 설정 | 이전 칸 방향만: `[[-1,0],[0,-1]]` |
| `memo = []` (리스트) | `memo = {}` (딕셔너리) |
| puddles 좌표를 변환 없이 `tuple(cur)`로 사용 | `for c, r in puddles: wall.add((r-1, c-1))` |
| move에 `[1, 0]` (아래 방향) 남아있었음 | Top-down에서는 이전 칸(위, 왼쪽)만 탐색 |
| `memo[x][y]`로 조회 (이중 인덱싱) | `memo[(x, y)]`로 조회 (튜플 키) |

## AI 코드 리뷰

### 개선할 점

1. **모듈러 반환값 불일치**: `memo[(x, y)] = result % 1000000007`로 저장하지만 `return result`로 모듈러 적용 안 된 값을 반환한다. 첫 호출은 모듈러 없이 반환되고, 캐시된 호출은 모듈러 적용된 값을 반환하여 불일치가 발생할 수 있다. 저장과 반환을 동일하게 맞춰야 한다.

2. **매직넘버 상수화**: `1000000007`이 여러 곳에 반복된다. `MOD = 1_000_000_007`로 상수를 선언하면 가독성과 유지보수성이 좋아진다.

3. **불필요한 sys.setrecursionlimit**: N, M ≤ 100이므로 최대 재귀 깊이는 약 198로, 파이썬 기본 재귀 제한(1000) 내에 충분하다. 불필요한 설정은 제거하는 것이 깔끔하다.

4. **Bottom-up DP 대안**: 이 문제는 Bottom-up이 더 간결하다. 재귀 오버헤드 없이 2중 for문으로 처리할 수 있어 코드가 짧고 직관적이다.

## 수정된 코드
```python
def solution(m, n, puddles):
    MOD = 1_000_000_007
    rows, cols = n, m
    wall = set()
    for c, r in puddles:
        wall.add((r - 1, c - 1))

    dp = [[0] * cols for _ in range(rows)]
    dp[0][0] = 1

    for x in range(rows):
        for y in range(cols):
            if (x == 0 and y == 0):
                continue
            if (x, y) in wall:
                dp[x][y] = 0
                continue
            top = dp[x - 1][y] if x > 0 else 0
            left = dp[x][y - 1] if y > 0 else 0
            dp[x][y] = (top + left) % MOD

    return dp[rows - 1][cols - 1]
```
