# 백준 1351 ♾️ 무한 수열 파이썬

## 느낀점
>
- 골드치고 생각보다 빠르게 잘 풀었다.
- N == 0일때 예제에 포함이 되어있지 않아다면 엣지케이스로 실패했을 것이다.
(엣지케이스 꼭 조심하자.)

## 흐름

1. N이 최대 10¹²이므로 배열 메모이제이션 불가 → 딕셔너리 메모이제이션 사용
2. A(0) = 1을 기저 조건으로 설정
3. A(i) = A(⌊i/P⌋) + A(⌊i/Q⌋)를 재귀적으로 계산
4. 이미 계산한 값은 딕셔너리에 저장하여 중복 계산 방지

## 코드
```python
import sys
input = sys.stdin.readline
N, P, Q = map(int, input().split())
mem = {0 : 1}
def s(n):
    if(n == 0):
        return 1
    a = int(n / P)
    b = int(n / Q)
    def find(num):
        if(num in mem):
            return mem[num]
        else:
            result = s(num)
            mem[num] = result
            return result
    aa = find(a)
    bb = find(b)
    return aa + bb
print(s(N))
```

## 질문 & 실수 정리

### 활용한 개념

#### 딕셔너리 메모이제이션 (희소 인덱스)
N이 10¹²처럼 매우 클 때 배열로 메모이제이션하면 메모리 초과가 발생한다. 하지만 실제로 계산되는 인덱스는 N을 P, Q로 반복 나눈 값들뿐이라 매우 적다 (약 O(log² N)개). 이런 경우 딕셔너리를 사용하면 필요한 인덱스만 저장하여 메모리를 절약할 수 있다.
- **핵심 원리**: 인덱스가 희소(sparse)할 때 배열 대신 딕셔너리로 메모이제이션
- **시간복잡도**: O(log P(N) × log Q(N)) — 실제 계산되는 서로 다른 상태 수

### 새로 배운 것

#### 중첩 함수의 호출 오버헤드
Python에서 함수 내부에 `def`로 중첩 함수를 정의하면, 외부 함수가 호출될 때마다 함수 객체가 새로 생성된다. 바이트코드를 재컴파일하는 건 아니고 이미 컴파일된 코드 객체를 참조하는 새 함수 객체를 만드는 것이라 한 번당 비용은 크지 않지만, 재귀처럼 수천~수만 번 호출되는 경우 누적 오버헤드가 발생한다.
- **핵심 원리**: 중첩 함수는 외부 함수 호출마다 함수 객체 생성 + 클로저 변수 캡처 비용이 발생하므로, 꼭 필요하지 않다면 바깥으로 빼거나 제거하는 것이 좋다

### 주의사항

| 틀린 것 | 올바른 것 |
|---|---|
| `int(n / P)` 사용 (부동소수점 나눗셈) | `n // P` 사용 (정수 나눗셈, 큰 수에서 안전) |

## AI 코드 리뷰

### 개선할 점

1. **`int(n / P)` → `n // P`**: `int(n / P)`는 부동소수점 연산을 거치므로 N이 클 때 정밀도 문제가 발생할 수 있다. `//` 연산자는 정수 나눗셈을 직접 수행하여 안전하다.

2. **내부 `find` 함수 제거**: `s` 함수가 호출될 때마다 `find` 함수가 새로 정의된다. `s` 함수 시작 부분에서 메모 체크를 하면 `find` 없이도 동일한 동작을 더 깔끔하게 구현할 수 있다.

3. **변수명 개선**: `s` → `solve`, `mem` → `memo`, `a/b/aa/bb` 같은 이름 대신 의미가 드러나는 이름을 사용하면 가독성이 높아진다.

## 수정된 코드
```python
import sys
input = sys.stdin.readline

N, P, Q = map(int, input().split())
memo = {0: 1}

def solve(n):
    if n in memo:
        return memo[n]
    result = solve(n // P) + solve(n // Q)
    memo[n] = result
    return result

print(solve(N))
```
