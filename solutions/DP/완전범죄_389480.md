## 실패한 코드 흐름
1. 완전탐색(DFS)으로 접근: 매 물건마다 A 또는 B가 훔치는 두 가지 경우를 재귀로 탐색
2. `a >= n`이거나 `b >= m`이면 가지치기로 중단
3. 모든 유효한 경우를 탐색하여 `found = min(a, found)`로 최솟값 갱신
4. 문제점: 물건 40개 → 2^40 ≈ 약 1조 경우의 수, 가지치기로도 최악의 경우를 보장할 수 없어 시간 초과

## 실패한 코드
```python
import sys
sys.setrecursionlimit(10**6)
def solution(info, n, m):
    def dfs(level, a, b):
        nonlocal found
        if(a >= n):
            return
        if(b >= m):
            return
        if(level == len(info)):
            found = min(a, found)
            return
        
        # B먼저 더하기 작업
        # 안되면 A 더하기 작업
        dfs(level + 1, a, b + info[level][1])
        dfs(level + 1, a + info[level][0], b)
    
    found = float('inf')
    result = dfs(0, 0, 0)
    if(found == float('inf')):
        return -1
    else:
        return found
```

**문제점**: `info = [[1,1]] * 40`, `n = m = 120`처럼 가지치기가 거의 안 되는 케이스에서 2^40에 가까운 탐색 → 시간 초과

## 성공한 코드 흐름

1. `dfs(level, b)` = "level번째 물건부터 끝까지 처리할 때, B 흔적이 현재 b인 상태에서 A 흔적의 최솟값을 반환"
2. 매 물건마다 A가 훔치는 경우(`dfs(level+1, b) + info[level][0]`)와 B가 훔치는 경우(`dfs(level+1, b + info[level][1])`) 중 최솟값 선택
3. `(level, b)` 상태를 딕셔너리에 메모이제이션하여 중복 계산 방지
4. 최종 답 `dfs(0, 0)`이 `n` 이상이면 불가능(-1), 아니면 그 값이 A의 최소 흔적

## 성공한 코드
```python
import sys
sys.setrecursionlimit(10**6)
def solution(info, n, m):
    # memo는 (level, b)를 넣으면 a의 최솟값을 알려준다.
    memo = {}
    
    def dfs(level, b):
        if((level, b) in memo):
            return memo[(level, b)]
        
        if(b >= m):
            return float('inf')
        if(level == len(info)):
            return 0
        pick_a = dfs(level+1, b) + info[level][0]
        pick_b = dfs(level+1, b + info[level][1])
        
        result = min(pick_a, pick_b)
        memo[(level, b)] = result
        return result
    
    answer = dfs(0, 0)
    
    if answer >= n:
        return -1
    else:
        return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### 백트래킹의 한계와 시간복잡도 분석
매 물건마다 A/B 두 갈래 선택 → 최악 2^40 ≈ 약 1조. 가지치기(`a >= n`, `b >= m`)를 넣어도, `info = [[1,1]] * 40`, `n = m = 120`처럼 흔적이 1씩만 쌓이고 한도는 120이면 거의 모든 경로에서 조건에 걸리지 않아 2^40에 가까운 탐색이 발생한다. 가지치기는 최선의 경우를 빠르게 해줄 뿐, 최악의 경우를 보장하지 못한다.

#### 메모이제이션 (DFS + 메모 = Top-down DP)
같은 입력에 대해 같은 결과를 반복 계산하지 않도록, 결과를 딕셔너리에 저장하고 재사용하는 기법. DFS + 메모이제이션 = Top-down DP.
- **시간복잡도**: 상태 수 × 상태당 연산 = O(len(info) × m)

**적용 조건: return 기반 구조**

`nonlocal`로 외부 변수를 수정하는 구조에서는 메모이제이션을 적용할 수 없다. 메모이제이션은 "같은 입력 → 같은 출력"을 저장하는 것이므로, 함수가 반드시 `return`으로 값을 돌려주는 구조여야 한다.

**사용법 1: 딕셔너리 방식**

```python
memo = {}
def dfs(state1, state2):
    # 1. 계산 전에 확인: 이미 계산한 적 있으면 바로 반환
    if (state1, state2) in memo:
        return memo[(state1, state2)]
    
    # 2. 계산 로직
    result = ...
    
    # 3. 결과를 딕셔너리에 저장 후 반환
    memo[(state1, state2)] = result
    return result
```

**사용법 2: @lru_cache 방식**

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def dfs(state1, state2):
    result = ...
    return result
# 딕셔너리 관리 없이 자동 캐싱. 단, 인자는 해시 가능한 타입(int, tuple 등)이어야 함.
```

**메모이제이션 적용 흐름**

1. `(level, b)`를 이미 계산한 적 있는지 확인 → 있으면 저장된 값 바로 반환
2. 기저 조건 체크 (`b >= m` → 불가능, `level == len(info)` → 0 반환)
3. 두 가지 선택 수행 (A가 훔치기 / B가 훔치기)
4. 둘 중 작은 값이 `result`
5. `memo[(level, b)]`에 `result` 저장
6. `result` 반환

#### 상태 축소: (level, a, b) → (level, b)
세 변수를 모두 상태로 쓰면 40 × 120 × 120 = 576,000이지만, 최적화 대상(A)을 반환값으로 빼면 40 × 120 = 4,800으로 120배 줄어든다. A를 최소화하는 게 목표이므로, `dfs(level, b)` → A의 최솟값 반환이 가장 자연스럽다. 반대로 `dfs(level, a)` → B의 최솟값 반환도 가능하지만, 마지막에 "A가 최소인 경우"를 따로 찾아야 해서 덜 직관적이다.

#### 기저 조건 return 0의 의미
`dfs(level, b)`는 "level번째부터 **추가되는** A 흔적의 최솟값"을 반환한다. `level == len(info)`이면 더 이상 물건이 없으므로 추가 A 흔적은 0이다. A의 총합은 재귀가 복귀하면서 `+ info[level][0]`이 누적되어 만들어진다.

```
dfs(0, 0) = dfs(1, 0) + info[0][0]
           = dfs(2, 0) + info[1][0] + info[0][0]
           = dfs(3, 0) + info[2][0] + info[1][0] + info[0][0]
           = 0         + 2          + 1           + 1   →   4
```

#### memo에 (level, b)로 저장하는 이유
`result = min(pick_a, pick_b)`는 `level+1`의 결과가 아니라, `level+1`의 결과에 현재 level의 비용을 더한 것들의 최솟값이다. 즉 "**현재 level부터** 끝까지의 A 최솟값"이므로 `memo[(level, b)]`에 저장하는 게 맞다.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| 2^40 완전탐색(DFS) 시도 | 메모이제이션으로 상태 수를 O(len(info) × m)으로 축소 |
| `nonlocal` 외부 변수 수정 구조 | `return` 기반 구조로 변경해야 메모이제이션 적용 가능 |

## AI 코드 리뷰

### 개선할 점

1. **Bottom-up DP로 전환**: 재귀 호출 + `sys.setrecursionlimit` 없이 반복문으로 처리 가능하다. `dp[b]` = 현재까지 처리한 물건에서 B 흔적이 b일 때 A의 최솟값으로 정의하면, 물건을 하나씩 순회하며 갱신할 수 있다.

2. **변수명 개선**: `b`가 "현재 B의 흔적 누적값"임을 주석 없이 알기 어렵다. `b_trace` 등으로 명확하게 할 수 있다.

## 수정된 코드
```python
def solution(info, n, m):
    INF = float('inf')
    # dp[b] = B의 흔적이 b일 때 A의 최소 흔적
    dp = [INF] * m
    dp[0] = 0

    for a_cost, b_cost in info:
        new_dp = [INF] * m
        for b_trace in range(m):
            if dp[b_trace] == INF:
                continue
            # A가 훔치는 경우: B 흔적 유지, A 흔적 증가
            new_a = dp[b_trace] + a_cost
            if new_a < new_dp[b_trace]:
                new_dp[b_trace] = new_a
            # B가 훔치는 경우: B 흔적 증가, A 흔적 유지
            new_b = b_trace + b_cost
            if new_b < m and dp[b_trace] < new_dp[new_b]:
                new_dp[new_b] = dp[b_trace]
        dp = new_dp

    result = min(dp)
    return result if result < n else -1
```
