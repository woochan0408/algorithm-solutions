## 흐름

1. 목표 고객 수 C와 도시 수 N, 각 도시별 (비용, 고객 수) 입력받기
2. dp 배열 크기를 C + max(고객 수) + 1로 설정 (C명 초과하는 경우가 더 저렴할 수 있으므로)
3. dp[0] = 0, 나머지는 inf로 초기화
4. 각 도시에 대해 고객 수부터 끝까지 정순 탐색하며 dp 갱신 (언바운디드 냅색)
5. dp[C:]의 최솟값이 답 ("적어도 C명" 조건)

## 코드
```python
import sys
input = sys.stdin.readline
cost = []
count = []
target, M = map(int, input().split()) 
for _ in range(M):
    cst, cnt = map(int, input().split())
    cost.append(cst)
    count.append(cnt)
rot = (target+max(count)) + 1
dp = [float('inf')] * rot
dp[0] = 0
#도시만큼
for i in range(M):
    cur_cost = cost[i]
    cur_count = count[i]
    
    for j in range(cur_count, rot):
        dp[j] = min(dp[j-cur_count] + cur_cost, dp[j])
print(min(dp[target::]))
```

## 질문 & 실수 정리

### 새로 배운 것

#### 언바운디드 냅색 (Unbounded Knapsack)
냅색 문제는 아이템을 **한 번만** 쓸 수 있는 0/1 냅색과, **무한번** 쓸 수 있는 언바운디드 냅색으로 나뉜다. 이 문제처럼 같은 도시에 정수배만큼 투자할 수 있는 경우가 언바운디드 냅색에 해당한다.

두 유형의 결정적인 차이는 **dp 탐색 순서**다.

**0/1 냅색 (각 아이템 1번만 사용)**
```python
for i in range(N):              # 아이템별
    for j in range(W, weight[i]-1, -1):  # 역순 탐색
        dp[j] = min(dp[j], dp[j - weight[i]] + cost[i])
```
역순으로 탐색하면 현재 아이템이 아직 반영되지 않은 이전 상태(`dp[j - weight[i]]`)를 참조하게 되어, 같은 아이템을 중복 사용하지 않는다.

**언바운디드 냅색 (각 아이템 무한번 사용)**
```python
for i in range(N):              # 아이템별
    for j in range(weight[i], W+1):      # 정순 탐색
        dp[j] = min(dp[j], dp[j - weight[i]] + cost[i])
```
정순으로 탐색하면 이미 현재 아이템이 반영된 상태를 참조하게 되어, 같은 아이템을 자연스럽게 여러 번 사용할 수 있다.

- **핵심 원리**: 탐색 순서(정순/역순)가 아이템 중복 사용 여부를 결정한다
- **시간복잡도**: O(N × W) (두 유형 모두 동일)

#### 반복문 구조의 동치성
언바운디드 냅색에서 아래 두 구조는 같은 결과를 낸다.

**구조 A: 바깥=도시, 안쪽=고객 수**
```python
for i in range(M):
    for j in range(count[i], rot):
        dp[j] = min(dp[j], dp[j - count[i]] + cost[i])
```

**구조 B: 바깥=고객 수, 안쪽=도시**
```python
for i in range(rot):
    for j in range(M):
        if i >= count[j]:
            dp[i] = min(dp[i], dp[i - count[j]] + cost[j])
```

0/1 냅색에서는 구조 A(바깥=아이템, 안쪽=용량, 역순)만 가능하지만, 언바운디드 냅색에서는 아이템이 이미 무한번 사용 가능하므로 순서를 뒤집어도 동일한 결과가 나온다.

#### 그리디 vs DP vs 백트래킹 — 이 문제에 적용
풀이를 고를 때 **그리디 → DP → 백트래킹** 순으로 적용 가능성을 따져보는 것이 최적화에 유리하다.

**1단계: 그리디로 풀 수 있나?**
"고객 1명당 비용이 가장 싼 도시만 반복 투자"하는 전략을 떠올릴 수 있다. 하지만 반례가 존재한다. 예제 1에서 도시1(3원/5명, 인당 0.6원)이 도시2(1원/1명, 인당 1원)보다 효율적이지만, 도시1만 쓰면 5명→10명→15명으로 12명을 딱 맞출 수 없어 15명에 9원이 든다. 실제 최적은 도시1×2 + 도시2×2 = 12명에 8원이다. 즉, **단일 기준의 탐욕 선택이 최적해를 보장하지 못한다.**

**2단계: DP로 풀 수 있나?**
"고객을 i명 늘리는 최소 비용"이라는 상태를 정의하면, 각 도시를 무한번 사용할 수 있으므로 **중복 부분 문제**가 존재한다. dp[j] = min(dp[j], dp[j - count] + cost)로 이전 상태를 재활용할 수 있다. → **DP 적용 가능!**

**3단계: 백트래킹은?**
각 도시를 몇 번 투자할지 모든 조합을 탐색하는 방식이다. 도시 i를 0 ~ C/count[i]번 선택할 수 있으므로, 최악의 경우(C=1000, N=20, 모든 count=1) 각 도시마다 0~1000번의 선택지가 생겨 탐색 공간이 O(C^N) = O(1000^20)에 달한다. 가지치기를 해도 10^7을 훨씬 넘기므로 시간초과가 난다. 반면 DP는 O(N × C) = O(20 × 1100) ≈ 22,000으로 여유롭게 통과한다.

#### 탑다운 vs 바텀업
탑다운(메모이제이션)과 바텀업(테이블) 중 어떤 것이 유리한지는 상황에 따라 다르다.

| | 탑다운 | 바텀업 |
|---|---|---|
| 장점 | 필요한 상태만 계산 (sparse할 때 유리) | 재귀 호출 오버헤드 없음 |
| 단점 | 재귀 스택 메모리 사용, 파이썬 재귀 제한 | 모든 상태를 계산 |

**상태 공간이 sparse할 때**(모든 상태를 방문하지 않아도 될 때) 탑다운이 메모리와 시간 모두 유리하고, **대부분의 상태를 방문해야 할 때**는 바텀업이 유리하다. 파이썬에서는 재귀 제한(기본 1000)과 재귀 오버헤드 때문에 바텀업을 선호하는 경우가 많다.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| `dp[M:]`으로 답 구함 (M은 도시 수) | `dp[target:]`으로 답 구함 (target이 목표 고객 수) |
| dp 크기에 `max(cost)` 사용 | dp 인덱스는 고객 수 기준이므로 `max(count)` 사용 |
| 백트래킹으로 접근 → 시간초과 | 언바운디드 냅색(DP)으로 풀이 |

## AI 코드 리뷰

### 개선할 점

1. **변수명 `rot`이 의미 불분명**: dp 배열의 크기를 나타내므로 `max_customers` 등 용도가 드러나는 이름으로 변경
2. **별도 리스트 `cost`, `count` 대신 튜플 리스트 사용**: 도시 정보를 하나의 리스트로 묶으면 관리가 편하고 가독성이 좋아짐
3. **변수명 `M`이 관례와 다름**: 보통 `N`이 개수를 의미하므로, 문제 원문에 맞춰 `C`, `N`으로 사용하면 혼동이 줄어듦

## 수정된 코드
```python
import sys
input = sys.stdin.readline

C, N = map(int, input().split())
cities = [tuple(map(int, input().split())) for _ in range(N)]

max_count = max(cnt for _, cnt in cities)
max_customers = C + max_count + 1

dp = [float('inf')] * max_customers
dp[0] = 0

for cost, count in cities:
    for j in range(count, max_customers):
        dp[j] = min(dp[j], dp[j - count] + cost)

print(min(dp[C:]))
```
