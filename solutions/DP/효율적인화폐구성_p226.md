## 흐름

1. N(화폐 종류), M(목표 금액) 입력받기
2. dp 배열을 M+1 크기로 생성, INF로 초기화 (dp[0] = 0)
3. 각 동전에 대해 정순 탐색하며 dp 갱신 (언바운디드 냅색)
4. dp[M]이 INF면 -1, 아니면 dp[M] 출력

## 코드
```python
import sys
INF = float('inf')
input = sys.stdin.readline
weight = []
N, M = map(int, input().split())
for i in range(N):
    weight.append(int(input()))
dp = [INF]*(M+1)
dp[0] = 0
for i in range(len(weight)):
    cur = weight[i]
    for j in range(cur, M+1):
        dp[j] = min(dp[j], dp[j - cur] + 1)
if(dp[M] == INF):
    print(-1)
else:
    print(dp[M])
```

## 질문 & 실수 정리

### 새로 배운 것

#### 언바운디드 냅색에서 "비용"이 고정인 경우
일반적인 언바운디드 냅색은 아이템마다 가치(weight)와 비용(cost)이 따로 있지만, 이 문제는 **동전 하나를 쓸 때마다 항상 +1**이라는 고정 비용 구조다. 호텔 문제(BOJ 1106)에서는 `dp[j - count] + cost`로 가변 비용을 더했지만, 여기서는 `dp[j - coin] + 1`로 단순화된다. 냅색의 핵심 구조(`dp[j] = min(dp[j], dp[j - 무게] + 비용)`)는 동일하고, "비용" 자리에 뭐가 들어가느냐만 달라진다.

#### 정순 vs 역순 탐색 — 왜 중복 사용 여부가 갈리는가
동전 = [3], 목표 = 9로 손 시뮬레이션하면 차이가 명확해진다.

**정순 (언바운디드):**
```
j=3: dp[3] = dp[0] + 1 = 1   ← 3원 1개
j=6: dp[6] = dp[3] + 1 = 2   ← dp[3]은 이미 갱신된 값(1) → 3원 2개
j=9: dp[9] = dp[6] + 1 = 3   ← dp[6]도 이미 갱신된 값(2) → 3원 3개
```
j=6을 계산할 때 dp[3]이 **이번 동전으로 이미 갱신된 상태**(1)라서, 같은 동전을 한 번 더 쓴 효과가 자연스럽게 생긴다.

**역순 (0/1):**
```
j=9: dp[9] = dp[6] + 1 = INF  ← dp[6]이 아직 INF (갱신 전)
j=6: dp[6] = dp[3] + 1 = INF  ← dp[3]도 아직 INF (갱신 전)
j=3: dp[3] = dp[0] + 1 = 1    ← 여기만 성공
```
역순이면 j=6 계산 시 dp[3]이 **아직 갱신 전**(INF)이라 참조할 수 없다. 결과적으로 3원짜리를 딱 1번만 쓸 수 있다.

| | 정순 | 역순 |
|---|---|---|
| dp[j-coin] 참조 시점 | 이번 동전으로 **이미 갱신된** 값 | 이번 동전이 **아직 반영 안 된** 값 |
| 효과 | 같은 동전 재사용 가능 | 같은 동전 1번만 사용 |
| 용도 | 언바운디드 냅색 | 0/1 냅색 |

#### 호텔(BOJ 1106) vs 화폐 구성 — 목표 조건의 차이
호텔 문제는 "C명 **이상**" 확보가 목표여서 dp 배열을 `C + max(count) + 1`로 넉넉히 잡고 `min(dp[C:])`로 답을 구했다. 반면 이 문제는 "정확히 M원"이어야 하므로 dp 크기는 `M + 1`이면 충분하고 `dp[M]` 하나만 확인한다. 불가능할 때도 호텔은 항상 해가 존재하지만, 화폐 구성은 INF 체크 후 -1을 출력해야 한다.

| | 호텔 (BOJ 1106) | 화폐 구성 (p226) |
|---|---|---|
| dp 인덱스 (j) | 고객 수 | 금액 |
| item_weight | 고객 수 (count) | 동전 가치 (coin) |
| item_cost | 비용 (cost) → 도시마다 다름 | 1 → 항상 고정 |
| 목표 | C명 **이상** → `min(dp[C:])` | M원 **정확히** → `dp[M]` |
| dp 크기 | C + max(count) + 1 | M + 1 |
| 불가능 처리 | 항상 가능 | INF면 -1 출력 |

#### dp 초기화: 0 vs INF는 냅색 유형이 아니라 문제 조건이 결정
INF 초기화는 0/1이냐 언바운디드냐와 무관하다. **"정확히 맞춰야 하는가"**에 따라 결정된다.

- **"최대한 채워라" (최대 가치)** → **0으로 초기화**. 안 채워도 되니까 모든 칸이 가치 0에서 시작.
- **"정확히 W를 만들어라" (최소 비용/개수)** → **INF로 초기화**. 아직 그 값을 만드는 방법을 못 찾았다는 의미. dp[0] = 0만 확정.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| 불가능한 경우 처리 누락 (INF 그대로 출력) | dp[M] == INF이면 -1 출력 |

## AI 코드 리뷰

### 개선할 점

1. **변수명 `weight` → `coins`**: 화폐 가치를 담는 리스트인데 `weight`는 무게를 연상시켜 혼동의 여지가 있음
2. **불필요한 인덱스 순회 제거**: `for i in range(len(weight)): cur = weight[i]` 대신 `for coin in coins:`로 직접 순회하면 가독성이 향상됨
3. **입력을 리스트 컴프리헨션으로 간결화**: 별도 리스트 선언 + for문 대신 한 줄로 처리 가능

## 수정된 코드
```python
import sys
INF = float('inf')
input = sys.stdin.readline

N, M = map(int, input().split())
coins = [int(input()) for _ in range(N)]

dp = [INF] * (M + 1)
dp[0] = 0

for coin in coins:
    for j in range(coin, M + 1):
        dp[j] = min(dp[j], dp[j - coin] + 1)

print(dp[M] if dp[M] != INF else -1)
