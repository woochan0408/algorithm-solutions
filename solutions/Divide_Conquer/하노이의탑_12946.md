## 흐름

1. 재귀 함수 `hanoi(src, target, inter, n)` 정의
2. base case: n == 1이면 src → target 이동 기록
3. recursive case:
   - n-1개를 src → inter로 이동 (target을 보조 기둥으로 사용)
   - 가장 큰 원판을 src → target으로 이동
   - n-1개를 inter → target으로 이동 (src를 보조 기둥으로 사용)
4. `hanoi(1, 3, 2, n)` 호출하여 1번 기둥에서 3번 기둥으로 이동

## 코드
```python
def solution(n):
    
    def hanoi(src, target, inter, n):
        if(n == 1):
            answer.append([src, target])
        else:
            hanoi(src, inter, target, n-1)
            hanoi(src, target, inter, 1)
            hanoi(inter, target, src, n-1)
    answer = []
    hanoi(1, 3, 2, n)
    return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### 재귀에서 파라미터 순서의 중요성
재귀 함수에서 파라미터의 의미(src, target, inter)와 실제 전달하는 인자의 순서가 정확히 일치해야 한다. 하노이 탑처럼 같은 함수를 역할만 바꿔서 호출하는 패턴에서는, 각 호출마다 "어디서 → 어디로, 보조는 어디"인지를 명확히 매핑해야 한다.
- **핵심 원리**: 파라미터 이름과 인자 위치가 불일치하면 전혀 다른 동작을 하게 됨
- **시간복잡도**: O(2ⁿ) — 원판 n개일 때 총 2ⁿ-1번 이동

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`hanoi(src, inter, target, n)` 순서로 정의 후 `hanoi(1, 3, 2, n)` 호출 → 1→2로 옮기는 결과|파라미터 순서를 `(src, target, inter, n)`으로 수정하여 `hanoi(1, 3, 2, n)`이 1→3 이동이 되도록 일치시킴|
|마지막 재귀 `hanoi(inter, target, src, n-1)` — 파라미터 순서 혼동으로 보조 기둥이 잘못 지정됨|파라미터 순서 변경 후 `hanoi(inter, target, src, n-1)`이 inter→target (src를 보조)로 정상 동작|

## AI 코드 리뷰

### 개선할 점

1. **불필요한 재귀 호출 제거**: `hanoi(src, target, inter, 1)`은 결국 `answer.append([src, target])`과 동일하다. 함수 호출 오버헤드 없이 직접 append하는 것이 더 명확하다.
2. **변수명 개선**: `inter` → `aux` (auxiliary)가 알고리즘 교재에서 더 보편적으로 사용되는 이름이다.

## 수정된 코드
```python
def solution(n):
    answer = []

    def hanoi(src, target, aux, n):
        if n == 1:
            answer.append([src, target])
            return
        hanoi(src, aux, target, n - 1)
        answer.append([src, target])
        hanoi(aux, target, src, n - 1)

    hanoi(1, 3, 2, n)
    return answer
```
