## 느낀점
>
- 백트래킹으로 구현했다.
- BFS - DFS 항상 헷갈리는데
    - 공통점 : 둘 다 탐색이다.
    (완전 탐색할거면 둘 다 사용 가능)
    - 하지만 완전탐색에서 BFS 불필요한 상태관리로 메모리 낭비
    - DFS는 상태를 전역관리할 수 있음
    -> 이게 바로 백트래킹 전략
    - 결국 최솟값 찾는건 -> BFS 전체 확인 -> DFS(백트래킹)
- 근데 이 문제는 그리디 문제였다..
- 나중에 그리디로 오답노트하자.

## 흐름

1. 피로도 테이블(`dic`)을 곡괭이 인덱스 × 광물 인덱스로 정의
2. 광물 리스트를 5개씩 그룹화하여 `mineral` 리스트 생성
3. DFS로 각 그룹마다 사용할 곡괭이를 선택하며 전체 경우 탐색
4. 곡괭이 사용 후 복원하는 백트래킹으로 최소 피로도 갱신

## 코드

```python
"""
5번 쓰면 못 씀
최소한의 피로도로 끝내고 싶음
곡괭이 아무거나 선택
다 쓸 때까지 변경 못 함
모든 광물을 캐거나 곡괭이 못 쓸 때까지
광물 순서는 정해져 있음
"""
dic = {0 : (1, 1, 1), 1: (5, 1, 1), 2: (25, 5, 1)}
def solution(picks, minerals):
    answer = float('inf')
    
    
    def dfs(n, p):
        nonlocal answer
        if(n == N or n == total):
            answer = min(answer, p)
            return
        
        for cur in [0, 1, 2]:
            if(picks[cur] > 0):
                picks[cur] -= 1
                cur_mineral = mineral[n]
                np = p
                for m in cur_mineral:
                    np += dic[cur][m]
                dfs(n+1, np)
                picks[cur] += 1
                
    mineral = []
    sub = []
    for cur in minerals:
        if(cur == 'stone'):
            sub.append(2)
        elif(cur == 'iron'):
            sub.append(1)
        else:
            sub.append(0)
            
        if(len(sub) == 5):
            mineral.append(sub)
            sub = []
    if(sub):
        mineral.append(sub)
    total = sum(picks)
    N = len(mineral)
    dfs(0, 0)
    return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### DFS 백트래킹 vs BFS 완전탐색
DFS와 BFS 모두 완전탐색이 가능하지만, 문제 특성에 따라 적합한 전략이 다르다. DFS 백트래킹은 하나의 전역 상태(예: `picks` 배열)를 공유하면서 변경 → 재귀 → 복원하는 방식으로 메모리를 절약하고, 탐색 도중 불필요한 분기를 가지치기로 일찍 끊을 수 있다. BFS는 큐에 모든 상태를 별도로 저장해야 해서 메모리 부담이 크다.
- **핵심 원리**: 상태가 커서 전역으로 관리하고 가지치기가 필요한 경우 → DFS 백트래킹이 유리. 최단 거리/최소 단계를 구하는 그래프 탐색 → BFS가 유리.

#### 백트래킹 시 상태 복원의 중요성
DFS에서 전역 상태를 변경한 후 재귀 호출이 끝나면 반드시 원래 값으로 복원해야 한다. `picks` 같은 객체는 복원했지만, 누적값인 `p`를 직접 `+=`로 변경하면 다른 분기에서 오염된 값이 사용된다. 새 변수(`np = p`)를 만들어 전달하면 원본이 보존된다.
- **핵심 원리**: 변경하는 상태 vs 전달하는 값을 명확히 구분

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`p += dic[cur][m]`으로 피로도 직접 누적 → 백트래킹 시 복원 안 됨|`np = p` 새 변수에 누적 후 `dfs(n+1, np)`로 전달|
|`stone=0, iron=1, diamond=2`로 인코딩 → `dic` 튜플 순서 `(다이아, 철, 돌)`과 불일치|`diamond=0, iron=1, stone=2`로 인코딩하여 `dic` 인덱스와 매칭|

## AI 코드 리뷰

### 개선할 점

1. **변수명 개선**: `dic`, `n`, `p`, `np`, `cur`, `m` 등이 의미를 전달하지 못함. `fatigue_table`, `group_idx`, `total_fatigue` 등으로 변경하면 가독성이 크게 향상됨

2. **가지치기 추가**: 현재 피로도가 이미 `answer` 이상이면 더 탐색할 필요 없음. `if np >= answer: continue`로 불필요한 재귀를 줄일 수 있음

3. **그리디 풀이 가능**: 광물 순서가 고정이므로 5개씩 그룹화한 후, 각 그룹의 "돌 곡괭이 기준 피로도"를 계산하여 내림차순 정렬 → 비용이 큰 그룹부터 좋은 곡괭이를 배정하면 O(N log N)으로 풀 수 있음

## 수정된 코드

```python
def solution(picks, minerals):
    FATIGUE = {0: (1, 1, 1), 1: (5, 1, 1), 2: (25, 5, 1)}
    MINERAL_MAP = {'diamond': 0, 'iron': 1, 'stone': 2}
    
    # 광물을 5개씩 그룹화
    groups = []
    for i in range(0, len(minerals), 5):
        chunk = [MINERAL_MAP[m] for m in minerals[i:i+5]]
        groups.append(chunk)
    
    total_picks = sum(picks)
    group_count = len(groups)
    min_fatigue = float('inf')
    
    def dfs(group_idx, fatigue):
        nonlocal min_fatigue
        
        if group_idx == group_count or group_idx == total_picks:
            min_fatigue = min(min_fatigue, fatigue)
            return
        
        for pick_type in range(3):
            if picks[pick_type] > 0:
                # 현재 그룹 피로도 계산
                group_fatigue = sum(FATIGUE[pick_type][m] for m in groups[group_idx])
                next_fatigue = fatigue + group_fatigue
                
                # 가지치기
                if next_fatigue >= min_fatigue:
                    continue
                
                picks[pick_type] -= 1
                dfs(group_idx + 1, next_fatigue)
                picks[pick_type] += 1
    
    dfs(0, 0)
    return min_fatigue
```

## 풀이 2 — 그리디

### 흐름

1. 광물을 5개씩 그룹화 (캘 수 있는 범위만큼만)
2. 각 그룹의 "돌 곡괭이 기준 피로도"를 계산 → 이 값이 클수록 다이아몬드가 많은 그룹
3. 피로도 내림차순 정렬 → 비용이 큰 그룹부터 좋은 곡괭이(다이아 → 철 → 돌) 순서로 배정
4. 곡괭이 순서가 고정이고 광물 순서도 고정이므로, 그룹 간 배정 순서만 결정하면 최적해

```python
def solution(picks, minerals):
    FATIGUE = {0: (1, 1, 1), 1: (5, 1, 1), 2: (25, 5, 1)}
    MINERAL_MAP = {'diamond': 0, 'iron': 1, 'stone': 2}
    
    total_picks = sum(picks)
    
    # 캘 수 있는 범위만 그룹화
    minable = minerals[:total_picks * 5]
    groups = []
    for i in range(0, len(minable), 5):
        chunk = [MINERAL_MAP[m] for m in minable[i:i+5]]
        groups.append(chunk)
    
    # 돌 곡괭이 기준 피로도로 내림차순 정렬
    groups.sort(key=lambda g: sum(FATIGUE[2][m] for m in g), reverse=True)
    
    # 좋은 곡괭이부터 비용 큰 그룹에 배정
    result = 0
    pick_idx = 0
    for group in groups:
        while pick_idx < 3 and picks[pick_idx] == 0:
            pick_idx += 1
        if pick_idx >= 3:
            break
        result += sum(FATIGUE[pick_idx][m] for m in group)
        picks[pick_idx] -= 1
    
    return result
```

## 시간복잡도 비교
### 백트래킹
- 각 그룹마다 곡괭이 3종을 선택
- 악 **O(3^N)** (N = 그룹 수, 최대 10)

### 그리디
- 그룹화 O(N) + 정렬 O(N log N) + 배정 O(N)
- **O(N log N)**
