# 프로그래머스 42885 🚤 구명보트 파이썬

## 느낀점
>
- 그리디를 왜이렇게 못 떠올리겠지..
- 이 문제는 3명 이상이 아닌 2명이라서 그리디가 가능

## 흐름

1. 정렬 후 가장 가벼운 사람(l)과 가장 무거운 사람(r) 비교
2. 둘의 합이 limit 이하면 같이 태움 → l 증가, r 감소
3. 초과하면 무거운 사람만 혼자 태움 → r만 감소
4. l == r이면 마지막 한 명 남은 것 → 보트 1개 추가 후 종료

## 코드
```python
def solution(people, limit):
    if(len(people) == 1):
        return 1
    
    people.sort()
    l = 0
    r = len(people)-1
    answer = 0
    while True:
        if(r < l):
            return answer
        if(l == r):
            return answer + 1
        if(people[l] + people[r] <= limit):
            answer += 1
            l += 1
            r -= 1
        else:
            answer += 1
            r -= 1
```

## 질문 & 실수 정리

### 새로 배운 것

#### 투 포인터 그리디
정렬 후 양쪽 끝에서 포인터를 좁혀가며 최적의 짝을 찾는 기법. 가장 무거운 사람이 가장 가벼운 사람과도 함께 탈 수 없다면, 그 사람은 누구와도 함께 탈 수 없으므로 혼자 보내는 것이 최적이다.
- **핵심 원리**: 정렬 + 양쪽 끝 비교로 매 단계 최선의 선택 보장
- **시간복잡도**: O(N log N) (정렬) + O(N) (탐색) = O(N log N)

#### 최대 탑승 인원 제한의 중요성
이 문제가 최대 2명이라는 제한이 없으면 **빈 패킹(Bin Packing)** 문제가 되어 NP-hard에 해당한다. 3명 이상 탑승 가능 시 그리디로는 최적해를 보장할 수 없고, 모든 조합을 따져야 하므로 효율적인 풀이가 존재하지 않는다.
- **핵심 원리**: 2명 제한 → 짝짓기 문제로 단순화 → 그리디 가능

## AI 코드 리뷰

### 개선할 점

1. **불필요한 엣지케이스 처리**: `len(people) == 1` 분기가 없어도 `while True` 루프의 `l == r` 조건에서 자연스럽게 처리됨.

2. **루프 구조 개선**: `while True` + 다중 return 대신 `while l <= r` 조건을 사용하면 루프 종료 조건이 명확해지고, 엣지케이스 분기도 불필요해짐.

## 수정된 코드
```python
def solution(people, limit):
    people.sort()
    l = 0
    r = len(people) - 1
    answer = 0

    while l <= r:
        if l < r and people[l] + people[r] <= limit:
            l += 1
        r -= 1
        answer += 1

    return answer
```
