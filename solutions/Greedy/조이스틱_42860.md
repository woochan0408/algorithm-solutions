## 실패한 코드 흐름
1. 각 위치별로 현재 위치에서 이동 거리 + 글자 변경 비용을 계산
2. 가장 비용이 작은 위치로 이동 (그리디 - 최근접 방문)
3. 방문한 위치를 리스트에서 제거하고 반복

## 실패한 코드
```python
def solution(name):
    
    answer = 0
    
    # 시작 -> 끝 이동 후 바꾸는 것 까지 값
    def calMove(si, ci):
        if(si > ci):
            si, ci = ci, si
            
        moveCount = min((si+N) - ci, ci - si)
        
        changeCount = min(ord(name[ci]) - ord('A'), ord('Z') - ord(name[ci]) + 1)
        
        return moveCount + changeCount
    
    N = len(name)
    leftIdx = [i for i in range(N)]
    for i in range(len(name)):
        if(name[i] == 'A'):
            leftIdx.remove(i)
    cur = 0
    
    # 현재 위치(0번) 먼저 처리
    if cur in leftIdx:
        answer += min(ord(name[cur]) - ord('A'), ord('Z') - ord(name[cur]) + 1)
        leftIdx.remove(cur)
    
    while leftIdx:
        # 이동거리 계산
        move = [float('inf') for _ in range(N)]
        minIdx = leftIdx[0]
        for i in leftIdx:
            move[i] = calMove(cur, i)
            if(move[minIdx] > move[i]):
                minIdx = i
        
        answer += move[minIdx]
        leftIdx.remove(minIdx)
        cur = minIdx
    return answer
```

**문제점**: 그리디(최근접 방문) 방식은 이동 비용과 변경 비용을 합산해서 가장 가까운 위치로 이동하는데, 이 방식은 커서 이동의 최적 경로를 보장하지 않는다. 커서 이동은 "오른쪽으로 갔다가 되돌아오기" 또는 "왼쪽으로 갔다가 되돌아오기" 중 최솟값을 구해야 하는 문제이므로, 매 순간 가장 가까운 곳으로 이동하는 그리디 접근은 전체 최적해를 보장할 수 없다.

## 성공한 코드 흐름

1. 글자 변경 비용과 커서 이동 비용을 분리해서 계산
2. **글자 변경 비용**: 각 문자마다 위로 올리기 vs 아래로 내리기 중 최솟값의 합
3. **커서 이동 비용**: 기본값은 오른쪽 끝까지 이동 (N-1)
4. 연속된 'A' 구간을 기준으로, "오른쪽으로 i까지 갔다가 되돌아와서 왼쪽으로" vs "왼쪽으로 먼저 갔다가 되돌아와서 오른쪽으로" 중 최솟값을 탐색

## 성공한 코드
```python
def solution(name):
    answer = 0
    N = len(name)
    
    # 글자 변경 비용
    for c in name:
        up = ord(c) - ord('A')       # 위로 올리기
        down = ord('Z') - ord(c) + 1  # 아래로 내리기
        answer += min(up, down)
    
    # 커서 이동 비용
    move = N - 1  # 기본값: 오른쪽 끝까지
    for i in range(N):
        # i 다음부터 연속된 A 구간의 끝 찾기
        next_i = i + 1
        while next_i < N and name[next_i] == 'A':
            next_i += 1
        # 오른쪽으로 i까지 갔다가 되돌아와서 왼쪽으로
        move = min(move, i * 2 + (N - next_i))
        # 왼쪽으로 먼저 갔다가 되돌아와서 오른쪽으로 i까지
        move = min(move, i + (N - next_i) * 2)
    
    answer += move
    return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### 그리디 vs 완전 탐색의 적용 기준
그리디 알고리즘은 매 순간 최선의 선택이 전체 최적해를 보장할 때만 사용할 수 있다. 이 문제에서 커서 이동은 "이동 비용 + 변경 비용"을 합산해서 가장 가까운 곳으로 이동하는 것이 전체 최소를 보장하지 않는다. 대신, 문제를 "변경 비용"과 "이동 비용"으로 분리하면 각각 독립적으로 최적화할 수 있다.
- **핵심 원리**: 문제를 독립적으로 최적화 가능한 부분 문제로 분리

#### 커서 이동 최적화 (연속 A 구간 활용)
커서 이동의 핵심은 연속된 'A' 구간을 건너뛰는 것이다. 오른쪽으로 i까지 갔다가 되돌아와서 왼쪽으로 가는 경로(i * 2 + 나머지)와, 왼쪽으로 먼저 갔다가 되돌아와서 오른쪽으로 가는 경로(나머지 * 2 + i)를 비교해서 최솟값을 구한다.
- **핵심 원리**: 한 방향으로 갔다가 되돌아오면 그 구간을 2번 지나게 되므로, 짧은 쪽을 2번 지나는 것이 유리

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`changeCount`를 위로 올리는 횟수만 계산|`min(위로, 아래로)` 비교 필요|
|'A'인 위치도 방문 대상에 포함|'A'는 변경 불필요하므로 제외|
|`del leftIdx[minIdx]` (인덱스 기준 삭제)|`leftIdx.remove(minIdx)` (값 기준 삭제)|
|`cur` 위치를 갱신하지 않음|이동 후 `cur = minIdx`로 갱신 필요|
|이동+변경을 합쳐서 그리디로 최근접 방문|이동과 변경을 분리하고, 이동은 연속 A 구간 기준으로 최적화|

## AI 코드 리뷰

### 개선할 점

1. **변수명 명확화**: `up`, `down`보다 `cost_up`, `cost_down`이 의미가 더 명확하다.
2. **주석 보강**: 커서 이동 최적화 부분의 두 가지 경우(오른쪽 먼저 vs 왼쪽 먼저)에 대한 주석이 있으면 나중에 복습할 때 이해가 빠르다.

## 수정된 코드
```python
def solution(name):
    answer = 0
    N = len(name)
    
    # 글자 변경 비용: 각 문자마다 위/아래 중 최솟값
    for c in name:
        cost_up = ord(c) - ord('A')
        cost_down = ord('Z') - ord(c) + 1
        answer += min(cost_up, cost_down)
    
    # 커서 이동 비용: 연속된 A 구간을 활용한 최적화
    move = N - 1
    for i in range(N):
        next_i = i + 1
        while next_i < N and name[next_i] == 'A':
            next_i += 1
        
        # 오른쪽(i까지) → 되돌아오기 → 왼쪽(나머지)
        move = min(move, i * 2 + (N - next_i))
        # 왼쪽(나머지) → 되돌아오기 → 오른쪽(i까지)
        move = min(move, i + (N - next_i) * 2)
    
    answer += move
    return answer
```
