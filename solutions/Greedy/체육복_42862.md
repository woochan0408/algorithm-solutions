# 프로그래머스 42862 👕 체육복 파이썬

## 느낀점
>
- 실수를 너무 많이했다..
- 굳이 투포인터로 풀 필요는 없어보이지만 시간복잡도 최적화를 연습하고 싶었다.

## 흐름

1. lost와 reserve를 정렬한다.
2. 투포인터로 양쪽 리스트에 모두 있는 학생(여벌이 있지만 도난당한 학생)을 먼저 제거한다.
3. 다시 투포인터를 돌려서 앞번호/뒷번호 매칭을 시도, 빌려줄 수 있는 수를 센다.
4. `n - (남은 lost 수 - 빌려준 수)`로 수업 가능한 학생 수를 구한다.

## 코드
```python
def solution(n, lost, reserve):
    canRent = 0
    
    lost.sort()
    reserve.sort()
    l = 0
    r = 0
    while l < len(lost) and r < len(reserve):
        curL = lost[l]
        curR = reserve[r]
        
        if(curL == curR):
            del lost[l]
            del reserve[r]
        elif(curL > curR):
            r += 1
        else:
            l += 1
    
    l = 0
    r = 0
    while True:
        if(l >= len(lost) or r >= len(reserve)):
            break
        curL = lost[l]
        curR = reserve[r]
        
        # 빌려줄 수 있다.
        if(curL == curR):
            l += 1
            r += 1
        elif(curL - 1 == curR or curL + 1 == curR):
            l += 1
            r += 1
            canRent += 1
        elif(curL + 1 < curR):
            l += 1
        elif(curL - 1 > curR):
            r += 1
    answer = n - (len(lost) - canRent)
    return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### 그리디에서 사전처리의 중요성
여벌을 가져왔지만 도난도 당한 학생은 빌려줄 수 없으므로, 매칭 로직에 들어가기 전에 양쪽 리스트에서 먼저 제거해야 한다. 사전처리 없이 매칭 로직 안에서 처리하려 하면 조건이 복잡해지고 예외 케이스가 생긴다.
- **핵심 원리**: 특수 조건(자기 자신에게 써야 하는 경우)을 먼저 걸러낸 후 일반 매칭을 수행

#### if와 elif 체이닝 차이
`if` → `if`로 이어 쓰면 앞 조건에서 상태가 변해도(del 등) 뒤 조건이 실행된다. 하나의 분기만 실행되어야 하는 경우 반드시 `if` → `elif` → `elif` 체인을 사용해야 한다.
- **핵심 원리**: 상호 배타적 조건은 반드시 elif로 연결

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|중복 학생 처리 없이 바로 매칭 시도|lost와 reserve 양쪽에 있는 학생을 사전처리로 제거|
|정렬 없이 투포인터 사용|투포인터 전에 반드시 sort() 필요|
|중복 제거 시 if/if 체인 사용|del 후 다른 분기 실행 방지를 위해 if/elif 체인 사용|

## AI 코드 리뷰

### 개선할 점

1. **`del` 대신 set 활용**: `del list[i]`는 O(n) 연산이다. 중복 제거는 set 연산으로 O(1)에 처리할 수 있다.

2. **두 번째 루프 스타일 통일**: 첫 번째 루프는 `while l < len(lost) and r < len(reserve)`인데, 두 번째 루프는 `while True` + 내부 break로 되어 있다. 같은 패턴으로 통일하면 가독성이 좋아진다.

3. **dead code 제거**: 사전처리에서 중복을 모두 제거했으므로 두 번째 루프의 `curL == curR` 분기는 절대 실행되지 않는다. 제거하는 것이 깔끔하다.

4. **변수명 개선**: `l`, `r`은 `1`과 혼동될 수 있고, `canRent`는 `matched` 등이 더 명확하다.

## 수정된 코드
```python
def solution(n, lost, reserve):
    # 사전처리: 여벌이 있지만 도난당한 학생 제거
    both = set(lost) & set(reserve)
    lost_set = sorted(set(lost) - both)
    reserve_set = sorted(set(reserve) - both)

    # 투포인터로 앞/뒷번호 매칭
    matched = 0
    li, ri = 0, 0
    while li < len(lost_set) and ri < len(reserve_set):
        lost_num = lost_set[li]
        reserve_num = reserve_set[ri]

        if lost_num - 1 == reserve_num or lost_num + 1 == reserve_num:
            matched += 1
            li += 1
            ri += 1
        elif lost_num + 1 < reserve_num:
            li += 1
        else:
            ri += 1

    return n - (len(lost_set) - matched)
```
