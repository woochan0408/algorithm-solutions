## 흐름

1. 체인 길이를 오름차순 정렬
2. 가장 짧은 체인부터 분해하여 연결 수단(고리)으로 사용
3. 현재 체인의 고리 수(`cur`)와 남은 체인을 하나로 연결하는 데 필요한 고리 수(`req = 남은 체인 수 - 1`)를 비교
   - `cur == req`: 딱 맞으므로 `cur`만큼 더하고 종료
   - `cur > req`: 고리가 남으므로 `req + 1`만큼 더하고 종료 (여분은 연결 후 다시 붙임)
   - `cur < req`: 현재 체인의 고리를 전부 사용하고, 뒤에서 `cur`개의 체인을 합침

## 코드
```python
import sys, math
from collections import deque
input = sys.stdin.readline
N = int(input())
arr = list(map(int, input().split()))
arr.sort()
dq = deque(arr)
answer = 0
while True:
    cur = dq.popleft()
    req = len(dq)-1
    if(cur == req):
        answer += cur
        break
    elif(cur > req):
        answer += req + 1
        break
    else:
        answer += cur
        for i in range(cur):
            dq.pop()
print(answer)
```

## 질문 & 실수 정리

### 새로 배운 것

#### 그리디 - 자원 분해 패턴
체인 문제에서 핵심은 **짧은 체인을 분해하여 연결 수단으로 재활용**하는 발상이다. 고리를 열면 그 고리 자체가 다른 체인을 이어주는 연결 고리가 되므로, 짧은 체인부터 분해하는 것이 손실을 최소화한다.
- **핵심 원리**: N개의 체인을 하나로 만들려면 N-1개의 연결이 필요하고, 고리 1개로 최대 2개의 체인을 연결할 수 있음. 짧은 체인부터 분해하면 전체 길이 손실이 최소화됨.

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|`ceil(N/2)`로 체인 길이를 무시한 접근|체인 길이에 따라 분해 가능한 고리 수가 달라지므로 길이를 반드시 고려해야 함|
|길이 1인지 아닌지만 중요하다고 판단|길이 2 이상의 체인도 고리를 떼어내면 길이 줄어든 체인 + 연결용 고리로 분리 가능|

## AI 코드 리뷰

### 개선할 점

1. **불필요한 deque + 반복 pop 제거**: `for i in range(cur): dq.pop()`은 pop한 값을 사용하지 않으므로 인덱스 기반 투 포인터로 대체하면 더 간결하고 효율적
2. **미사용 import 제거**: `math`를 import하지만 최종 코드에서 사용하지 않음
3. **미사용 루프 변수**: `for i in range(cur)`에서 `i`를 사용하지 않으므로 `_`로 표기하는 것이 관례

## 수정된 코드
```python
import sys
input = sys.stdin.readline

N = int(input())
arr = sorted(map(int, input().split()))

answer = 0
left = 0
right = N - 1

while left <= right:
    cur = arr[left]
    remaining = right - left  # 남은 체인 수 (자신 제외)
    req = remaining - 1       # 연결에 필요한 고리 수

    if cur >= req:
        answer += req + 1
        break
    else:
        answer += cur
        right -= cur  # 뒤에서 cur개 체인을 연결 처리
        left += 1
    
print(answer)
```
