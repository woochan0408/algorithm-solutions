# 프로그래머스 340198 🏕️ 공원 파이썬

## 느낀점
>
- 파싱 순서 조심하자... 항상 틀린다.

## 흐름

1. 공원의 모든 칸을 돗자리의 왼쪽 위 시작점으로 확인한다.
2. 각 시작점에서 `mats`에 들어 있는 돗자리 크기를 하나씩 검사한다.
3. `can(i, j, size)`에서 해당 크기의 정사각형 영역이 공원 범위를 벗어나지 않는지 확인한다.
4. 영역 안의 모든 값이 빈자리인 문자열 `"-1"`인지 확인한다.
5. 현재 위치에 놓을 수 있는 가장 큰 돗자리 한 변의 길이를 구해 전체 최댓값을 갱신한다.
6. 어떤 돗자리도 놓을 수 없다면 `-1`을 반환한다.

## 코드

```python
def solution(mats, park):
    def can(i, j, size):
        for row in range(i, i + size):
            for col in range(j, j + size):
                if not (0 <= row < len(park)):
                    return False

                if not (0 <= col < len(park[0])):
                    return False

                if park[row][col] != "-1":
                    return False

        return True

    def max_value(i, j):
        result = -1

        for size in mats:
            if can(i, j, size):
                result = size if size > result else result

        return result

    answer = -1

    for i in range(len(park)):
        for j in range(len(park[0])):
            answer = max_value(i, j) if max_value(i, j) > answer else answer

    return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### 2차원 리스트의 행과 열

2차원 리스트는 `park[행][열]` 순서로 접근한다. 행의 개수는 `len(park)`, 열의 개수는 `len(park[0])`이다. 행과 열의 기준을 처음부터 고정하면 범위 검사와 인덱싱이 뒤바뀌는 실수를 줄일 수 있다.

- **핵심 원리**: 바깥 리스트의 인덱스가 행이고, 각 행 내부 리스트의 인덱스가 열이다.
- **시간복잡도**: 특정 칸 접근은 `O(1)`이다.

#### 같은 함수 호출 결과 재사용

함수 호출 결과가 변하지 않는 상황에서 같은 인자로 함수를 여러 번 호출하면 불필요한 연산이 반복된다. 특히 `max_value(i, j)` 내부에서는 여러 돗자리와 여러 칸을 다시 검사하므로 한 번의 호출 비용이 작지 않다.

- **핵심 원리**: 한 번 계산한 결과는 변수에 저장해 비교와 대입에 재사용한다.
- **시간복잡도**: 점근적 복잡도는 같지만 중복 호출만큼 실제 실행량이 증가한다.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| 행의 범위를 `len(park[0])`과 비교 | 행의 범위는 `len(park)`과 비교 |
| 열의 범위를 `len(park)`과 비교 | 열의 범위는 `len(park[0])`과 비교 |
| `park[col][row]`로 접근 | `park[row][col]`로 접근 |
| 빈자리를 정수 `-1`과 비교 | 빈자리를 문자열 `"-1"`과 비교 |
| 가로와 세로 크기를 별도로 조합 | 정사각형이므로 하나의 `size`만 사용 |
| 놓을 수 있는 돗자리의 넓이를 저장 | 한 변의 길이 `size`를 저장 |
| `max_value(i, j)`를 조건식 안에서 반복 호출 | 호출 결과를 저장하거나 반복 호출이 필요 없는 흐름으로 변경 |

## AI 코드 리뷰

### 잘한 점

1. **검사 로직을 함수로 분리함**: 특정 위치에 돗자리를 놓을 수 있는지 확인하는 코드를 `can`으로 분리해 전체 흐름을 이해하기 쉽다.
2. **범위를 벗어나거나 사람이 있는 즉시 종료함**: 실패 조건을 발견하면 바로 `False`를 반환해 남은 칸을 불필요하게 확인하지 않는다.
3. **놓을 수 없는 경우를 자연스럽게 처리함**: `answer`와 `result`를 `-1`로 시작해 가능한 돗자리가 없을 때 별도 예외 처리 없이 요구사항을 만족한다.
4. **제한사항 안에서 충분히 통과 가능한 접근임**: 공원의 최대 크기가 `50 × 50`, 돗자리 종류가 최대 10개이므로 완전탐색으로 해결할 수 있다.

### 개선할 점

1. **변수명에 역할을 드러내기**: `i`, `j`보다 `start_row`, `start_col`이 해당 좌표가 돗자리의 시작점이라는 의미를 더 분명하게 전달한다. `can`도 `can_place_mat`처럼 동작을 구체적으로 표현할 수 있다.
2. **행과 열의 길이를 미리 저장하기**: `len(park)`와 `len(park[0])`을 `row_count`, `col_count`로 저장하면 의미가 명확해지고 반복 표현도 줄어든다.
3. **같은 위치에서 `max_value`를 반복 호출하지 않기**: 현재 조건식은 `max_value(i, j)`를 한 번 또는 두 번 실행한다. 호출 결과를 저장하면 같은 영역을 다시 검사하지 않아도 된다.
4. **가장 큰 돗자리부터 검사하기**: `mats`를 내림차순으로 정렬하면 처음 놓을 수 있는 돗자리가 곧 정답이다. 이후 더 작은 돗자리는 확인하지 않아도 된다.
5. **가능한 시작점만 순회하기**: 시작 좌표의 범위를 `row_count - size + 1`, `col_count - size + 1`까지만 제한하면 `can` 내부에서 매 칸마다 경계 검사를 하지 않아도 된다.
6. **`max_value` 함수 제거하기**: 큰 돗자리부터 탐색하고 성공 즉시 반환하면 위치별 최댓값을 별도로 계산할 필요가 없어 전체 구조가 단순해진다.

### 시간복잡도

현재 코드는 공원의 행 수를 `R`, 열 수를 `C`, 돗자리 종류 수를 `K`, 가장 긴 한 변을 `S`라고 할 때 최악의 경우 `O(R × C × K × S²)`이다. 조건식에서 `max_value`가 반복 호출되므로 실제 연산은 일부 위치에서 두 배 가까이 증가할 수 있다.

수정된 코드도 최악의 점근적 복잡도는 `O(K × R × C × S²)`이지만, 큰 돗자리부터 검사해 정답을 찾는 즉시 종료하고 가능한 시작 좌표만 순회하므로 실제 수행량과 코드 복잡도가 줄어든다. `mats` 정렬에는 `O(K log K)`가 추가되며, `K ≤ 10`이라 부담이 매우 작다.

## 수정된 코드

```python
def solution(mats, park):
    row_count = len(park)
    col_count = len(park[0])

    def can_place_mat(start_row, start_col, size):
        for row in range(start_row, start_row + size):
            for col in range(start_col, start_col + size):
                if park[row][col] != "-1":
                    return False

        return True

    for size in sorted(mats, reverse=True):
        if size > row_count or size > col_count:
            continue

        for start_row in range(row_count - size + 1):
            for start_col in range(col_count - size + 1):
                if can_place_mat(start_row, start_col, size):
                    return size

    return -1
```
