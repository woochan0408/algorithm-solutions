# 백준 14594 🚪 동방 프로젝트 (Small) 파이썬
## 느낀점
>
- union?, 딕셔너리? 여러 생각이 나는 좋은 문제다.
- 일단 Small 문제는 브루트포스로 풀고 Large는 저녁에 다시 풀어보려 한다.

## 흐름
처음에 방의 개수를 `N`개로 두고, 각 방이 **새로운 동방의 시작점인지**를 불리언 배열로 관리했다.

- 처음에는 모든 방이 독립적이므로 전부 `True`로 둔다.
- `a b`가 들어오면 `a`번 방부터 `b`번 방 사이의 벽이 무너지므로, `a+1`번 방부터 `b`번 방까지는 더 이상 새로운 동방의 시작점이 아니게 된다.
- 그래서 배열에서 `a`부터 `b-1` 구간을 `False`로 바꾼다.
- 마지막에 `True`의 개수를 세면 남아 있는 동방 수가 된다.

## 코드
```python
'''
5
2
1 2
2 4

재밌는 문제다
'''
import sys
input = sys.stdin.readline

N = int(input())
M = int(input())
wall = [True]*(N)

for _ in range(M):
    a, b = map(int, input().split())
    for i in range(a, b):
        wall[i] = False
print(sum(wall))
```
## 개선할 점

1. **변수명**: `wall`은 실제로는 "벽 존재 여부"라기보다 "해당 방이 새로운 동방의 시작점인지"를 저장하는 역할에 가깝다. 그래서 의미가 드러나는 이름으로 바꾸면 읽기가 더 쉬워진다.

2. **불리언 배열 의도 드러내기**: 현재 코드는 `sum(wall)`로 정답을 구해서 간결하다. 다만 처음 보는 사람은 왜 불리언 배열을 더했는지 바로 이해하지 못할 수 있으니, 배열의 의미를 짧게 주석으로 남기면 가독성이 좋아진다.

3. **테스트용 문자열 분리**: 파일 맨 위의 예제 입력용 문자열은 풀이 기록에는 괜찮지만, 제출 코드와 함께 있을 때는 실제 코드 흐름과 섞여 보일 수 있다. 리뷰 문서에서는 유지해도 되지만, 최종 정리본에서는 테스트 입력 메모와 제출 코드를 분리해두는 편이 깔끔하다.

## 수정된 코드
```python
import sys
input = sys.stdin.readline

N = int(input())
M = int(input())

# True면 해당 방이 하나의 동방 시작점이라는 뜻
room_start = [True] * N

for _ in range(M):
    left, right = map(int, input().split())

    for room in range(left, right):
        room_start[room] = False

print(sum(room_start))
```
