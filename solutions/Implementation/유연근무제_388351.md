# 프로그래머스 388351 ⏰ 유연근무제 파이썬

## 느낀점
>
- 기본문제에 35분을 태웠다.
- 문제를 제대로 안 읽은 탓에 디버깅 하느라 시간이 오래걸렸다.
- 삽질 조심하자..!!

## 흐름

1. `시 * 100 + 분` 형태의 시간을 모두 분 단위로 변환한다.
2. 직원별 출근 희망 시각에 10분을 더해 출근 인정 마감 시각을 구한다.
3. `startday`와 경과 일수를 이용해 각 기록의 요일을 계산한다.
4. 토요일과 일요일 기록은 검사하지 않는다.
5. 평일 중 하루라도 마감 시각보다 늦게 출근했다면 해당 직원은 상품 대상에서 제외한다.
6. 모든 평일에 늦지 않은 직원의 수를 센다.

## 코드

```python
'''
유연근무제
출근 희망 시각에 늦지 않으면 상품

출근 희망 시각 + 10분 까지 도착해야함
토요일 일요일은 이벤트 X
시 * 100 + 분 정수로 시간 표현

n명의 직원
이벤트 시작요일 startday
상품 받을 직원의 수
1이 월요일

이분탐색도 가능할 것 같음

7 나머지가 6과 0이면 해당 안함
'''


def solution(schedules, timelogs, startday):


    def receive_gift(target, time, i):
        print(target, time, i)
        time = (time//100)*60 + time%100
        target = (target//100)*60 + target%100

        # 토요일이나 일요일
        if(i%7 == 6 or i%7 == 0):
            return True

        if(target+10 >= time):
            return True
        return False


    answer = 0
    n = len(schedules)

    for person in range(n):
        print(person)
        result = True
        for t in range(7):
            time = (startday+t)%7

            cur_result = receive_gift(schedules[person], timelogs[person][t], time)
            print(cur_result)
            if not cur_result:
                result = False
                break

        if result:
            answer += 1
    return answer
```

## 질문 & 실수 정리

### 새로 배운 것

#### `HHMM` 형식의 시간을 분 단위로 변환하기

`958`, `1013`처럼 시와 분이 합쳐진 정수는 일반 정수처럼 바로 덧셈하거나 비교하기보다 분 단위로 변환하면 안전하다.

- **핵심 원리**: `시 = time // 100`, `분 = time % 100`
- **변환식**: `(time // 100) * 60 + time % 100`
- **시간복잡도**: O(1)

예를 들어 `958`은 `9 * 60 + 58 = 598분`이고, 여기에 10분을 더하면 `608분`, 즉 10시 8분이 된다.

#### 나머지 연산으로 요일 순환하기

일주일은 7일마다 반복되므로 시작 요일과 경과 일수를 이용해 현재 요일을 계산할 수 있다.

- **핵심 원리**: `(startday - 1 + day_offset) % 7 + 1`
- 계산 결과를 문제와 동일하게 월요일 `1`부터 일요일 `7`까지 유지하면 주말 판별이 직관적이다.
- **시간복잡도**: O(1)

#### 조건을 만족하지 않으면 즉시 종료하기

한 직원이 평일 중 하루라도 늦으면 상품을 받을 수 없으므로 나머지 출근 기록은 확인할 필요가 없다.

- **핵심 원리**: 지각을 발견하는 즉시 `break`
- 최악의 경우 직원마다 7일을 확인하지만, 지각이 일찍 발견되면 불필요한 검사를 줄일 수 있다.

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|이분 탐색 사용을 고려함|출근 기록은 정렬된 탐색 대상이 아니며, 각 평일의 조건을 직접 확인해야 한다.|
|`(startday + t) % 7`로 일요일을 `0`으로 표현함|`(startday - 1 + t) % 7 + 1`을 사용하면 문제의 요일 표현인 `1~7`을 그대로 유지할 수 있다.|
|`print()` 디버깅 코드가 남아 있음|제출 및 정리 코드에서는 디버깅 출력을 제거한다.|
|출근 희망 시각을 매일 분으로 다시 변환함|직원별 출근 마감 시각은 한 번만 계산해서 재사용한다.|
|`receive_gift`, `i`, `time`처럼 역할이 넓거나 모호한 이름을 사용함|`is_valid_attendance`, `day_of_week`, `arrival_time`처럼 역할이 드러나는 이름을 사용한다.|

## AI 코드 리뷰

### 개선할 점

1. **보조 함수의 역할 분리**: 시간 변환만 담당하는 `to_minutes` 함수를 두면 요일 판별과 출근 시각 검사가 섞이지 않는다.
2. **변수명 구체화**: `person`, `t`, `time`, `result`보다 `employee_logs`, `day_offset`, `arrival_time`, `is_eligible`이 의미를 바로 전달한다.
3. **요일 표현 통일**: 문제에서 사용하는 월요일 `1`부터 일요일 `7`까지의 범위를 유지하면 `day_of_week >= 6`만으로 주말을 판별할 수 있다.
4. **중복 계산 제거**: 직원의 출근 인정 마감 시각은 7일 동안 같으므로 직원마다 한 번만 계산한다.
5. **불필요한 탐색 제거**: 이분 탐색은 필요하지 않다. 직원마다 최대 7개의 기록만 확인하므로 단순 순회가 가장 자연스럽고 충분히 빠르다.

### 개선된 흐름

1. 시간 정수를 분 단위로 변환하는 함수를 만든다.
2. 직원과 해당 직원의 일주일 기록을 `zip`으로 함께 순회한다.
3. 직원별 출근 인정 마감 시각을 한 번 계산한다.
4. 각 기록의 요일을 `1~7` 범위로 계산한다.
5. 주말은 건너뛰고, 평일에 지각한 기록이 있으면 즉시 반복을 종료한다.
6. 지각한 평일이 없는 직원만 정답에 추가한다.

- **시간복잡도**: O(n × 7) = O(n)
- **공간복잡도**: O(1)

## 수정된 코드

```python
def solution(schedules, timelogs, startday):
    def to_minutes(time):
        hour = time // 100
        minute = time % 100
        return hour * 60 + minute

    answer = 0

    for schedule, employee_logs in zip(schedules, timelogs):
        deadline = to_minutes(schedule) + 10
        is_eligible = True

        for day_offset, arrival_time in enumerate(employee_logs):
            day_of_week = (startday - 1 + day_offset) % 7 + 1

            if day_of_week >= 6:
                continue

            if to_minutes(arrival_time) > deadline:
                is_eligible = False
                break

        if is_eligible:
            answer += 1

    return answer
```
