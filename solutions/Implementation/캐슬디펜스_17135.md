## 흐름

1. 격자판에서 적의 위치를 리스트로 저장
2. 궁수 3명의 배치를 조합(combinations)으로 모든 경우 탐색
3. 각 조합마다 시뮬레이션 반복:
   - 궁수 3명이 각각 타겟 선정 (거리 D 이하, 가장 가까운 적, 같으면 가장 왼쪽)
   - 타겟을 set으로 모아 중복 제거 후 한꺼번에 제거 (동시 공격)
   - 적 한 칸 아래로 이동, 성에 도달한 적 제거
4. 모든 조합 중 최대 제거 수 출력

## 질문 & 실수 정리

### 새로 배운 것

#### copy.deepcopy
중첩 리스트(2차원 리스트 등)를 복사할 때, 단순 슬라이싱(`list[:]`)이나 `list.copy()`는 내부 리스트의 참조만 복사하는 얕은 복사(shallow copy)다. 내부 리스트를 수정하면 원본도 같이 바뀌기 때문에, 시뮬레이션처럼 원본을 보존하면서 복사본을 조작해야 하는 경우 `copy.deepcopy()`로 깊은 복사를 해야 한다.
- **핵심 원리**: 객체 내부의 모든 중첩 객체까지 재귀적으로 새 객체를 생성하여 완전히 독립된 복사본을 만듦
- **시간복잡도**: O(n) (전체 원소 수에 비례)

### 실수했던 부분

#### 리스트 순회 중 remove
리스트를 for문으로 순회하면서 `remove()`로 원소를 삭제하면, 뒤쪽 원소의 인덱스가 앞으로 당겨져 원소를 건너뛰거나 `IndexError`가 발생한다. 삭제할 원소를 별도 리스트에 모은 뒤 나중에 제거하거나, 리스트 컴프리헨션으로 새 리스트를 만들어야 한다.

|틀린 것|올바른 것|
|---|---|
|순회 중 `enemy.remove(enemy[i])`|삭제 대상을 `delList`에 모아서 나중에 제거|

#### attack 함수 변수 스코프
`canAttack`을 정렬한 뒤 반환할 때, 정렬된 첫 번째 원소가 아니라 for문의 마지막 반복에서 남은 `ex, ey`를 반환했다. 정렬한 의미가 사라지고 엉뚱한 적을 공격하게 된다.

|틀린 것|올바른 것|
|---|---|
|`return [ex, ey]` (for문 마지막 값)|`return [canAttack[0][1], canAttack[0][2]]`|

#### 동시 공격 미처리
궁수가 순차적으로 공격하면서 바로 `enemy`에서 제거하면, 같은 적을 두 궁수가 공격할 때 중복 카운트되거나 두 번째 궁수의 탐색 결과가 달라진다. set으로 타겟을 모아 중복 제거 후 한꺼번에 제거해야 한다.

|틀린 것|올바른 것|
|---|---|
|궁수마다 즉시 제거 + 카운트|set으로 타겟 수집 → 중복 제거 → 일괄 제거|

#### 정렬 기준 오류
`(d, ex, ey)` 순 정렬은 거리가 같을 때 행(ex)을 먼저 비교한다. 문제 조건은 "가장 왼쪽", 즉 열(ey)이 작은 적을 먼저 공격해야 한다.

|틀린 것|올바른 것|
|---|---|
|`sort()` → `(d, ex, ey)` 기본 정렬|`sort(key=lambda x: (x[0], x[2], x[1]))` 거리→열→행|

#### enemy_copy vs enemy 혼용
`attack`에서는 `enemy_copy`를 탐색하면서, 제거와 이동에서는 `enemy`를 조작해 시뮬레이션이 엉망이 됐다. 복사본 기준으로 통일해야 한다.

|틀린 것|올바른 것|
|---|---|
|`enemy.remove([x, y])`|`enemy_copy.remove([x, y])`|

## AI 코드 리뷰

### 개선할 점

1. **미사용 코드 제거**: `grid` 리스트와 성 표시용 `arr = [2]*M`은 실제 로직에서 사용되지 않는다. 적 위치를 `enemy` 리스트로 관리하므로 격자판 자체는 불필요하다.

2. **`enemy_copy`를 전역 변수로 참조**: `attack` 함수가 외부의 `enemy_copy`를 직접 참조하고 있다. 함수 인자로 전달하면 의존성이 명확해지고 디버깅이 쉬워진다.

3. **`list.remove()` 반복 호출**: `remove()`는 매번 O(n) 탐색을 하므로, 적이 많아지면 비효율적이다. 삭제 대상을 set으로 관리하고 리스트 컴프리헨션으로 한 번에 필터링하는 것이 효율적이다.

4. **불필요한 초기 정렬**: `enemy.sort(key=lambda x: -x[0])`는 이동 시 겹침 방지를 위해 추가했지만, 이동 로직이 `delList` 방식으로 바뀌면서 실질적 효과가 없다.

## 수정된 코드
```python
import sys, copy
from itertools import combinations

input = sys.stdin.readline
N, M, D = map(int, input().split())

enemy = []
for i in range(N):
    row = list(map(int, input().split()))
    for j in range(M):
        if row[j] == 1:
            enemy.append([i, j])


def find_target(ax, ay, enemies):
    """궁수 (ax, ay)가 공격할 타겟을 찾아 반환"""
    best = None
    for ex, ey in enemies:
        d = abs(ax - ex) + abs(ay - ey)
        if d <= D:
            if best is None or (d, ey, ex) < (best[0], best[1], best[2]):
                best = (d, ey, ex)
    if best:
        return (best[2], best[1])  # (행, 열)
    return None


answer = 0
for archers in combinations(range(M), 3):
    result = 0
    enemies = copy.deepcopy(enemy)

    while enemies:
        # 1. 궁수 3명 동시에 타겟 선정
        targets = set()
        for a in archers:
            target = find_target(N, a, enemies)
            if target:
                targets.add(target)

        # 2. 타겟 일괄 제거
        result += len(targets)
        enemies = [e for e in enemies if tuple(e) not in targets]

        # 3. 적 이동 (성 도달 시 제거)
        enemies = [[r + 1, c] for r, c in enemies if r + 1 < N]

    answer = max(answer, result)

print(answer)
```
