## 잘못 해석한 문제

> 박사님이 N/2마리를 주는 건 맞지만, 주는 방식이 "자유롭게 골라가"가 아니라:
> 1. 박사님의 폰켓몬 종류별 개수가 **균등해질 때까지** 하나씩 빼서 나에게 준다
> 2. 빼줄 때 나는 **종류가 최대한 많아지도록** 선택한다
>
> 예시: `[3,3,3,2,2,4]` → 빈도 `{3:3, 2:2, 4:1}`
> - 3번이 가장 많으니까 3번 하나 빼서 나에게 줌 → `{3:2, 2:2, 4:1}` / 나: `{3:1}`
> - 3번, 2번이 4번보다 많으니까 또 빼줌 → 이때 나는 종류 다양하게 받으려 함
> - 균등해지면 종료

## 잘못 해석한 흐름

1. 빈도 배열 `po`를 만들어 각 폰켓몬 종류의 등장 횟수를 센다
2. `counter` 딕셔너리에 빈도(개수)를 key로, 해당 빈도를 가진 종류 번호들을 value로 그룹핑
3. 가장 높은 빈도 그룹부터 순회하며 하나씩 빼서 균등하게 만든다
4. 빼는 과정에서 나에게 주는 종류 수를 최대화

## AI 코드 리뷰 (실패한 코드)

### 개선할 점

1. **`len(nums+1)` TypeError**: `nums`는 리스트이고 `1`은 정수이므로 리스트와 정수를 더할 수 없다. 종류 번호를 인덱스로 쓰려면 `max(nums) + 1`이어야 한다.

2. **카운트 방향 오류**: `po[cur] -= 1`로 되어 있는데, 빈도를 올려야 하므로 `po[cur] += 1`이 맞다.

3. **`counter` 그룹 이동 비효율**: `counter[cur_count].remove(cur)`는 리스트에서 O(N) 탐색이 발생한다. 빈도 카운팅은 `collections.Counter`를 쓰면 한 줄로 해결된다.

4. **불필요한 복잡도**: 잘못 해석한 문제라 해도, 빈도를 세는 단계와 균등화하는 단계를 분리하면 훨씬 깔끔하다. 빈도를 먼저 `Counter`로 구한 뒤, 정렬해서 위에서 깎아내리는 방식이 자연스럽다.

## 수정된 코드 (잘못 해석한 문제 기준)

```python
from collections import Counter

def solution(nums):
    count = Counter(nums)
    min_freq = min(count.values())

    # 균등해질 때까지 빼준 폰켓몬에서 종류 수 최대화
    # min_freq보다 많은 종류에서 초과분이 나에게 옴
    # → 초과분이 있는 종류에서 최소 1마리씩 받을 수 있음
    received_types = sum(1 for freq in count.values() if freq > min_freq)

    return received_types
```

## 실제 문제 흐름

1. 전체 종류 수 = `set(nums)`의 길이
2. 가져갈 수 있는 마리 수 = `N/2`
3. 답은 두 값 중 작은 값 → `min(전체 종류 수, N/2)`

## 코드

```python
def solution(nums):
    
    return min(len(set(nums)), len(nums)/2)
```

## 질문 & 실수 정리

### 새로 배운 것

#### set을 활용한 종류 수 계산
리스트에서 중복을 제거하고 고유한 원소의 개수를 구할 때 `set()`으로 변환하면 O(N)에 처리할 수 있다.
- **핵심 원리**: 해시 기반 자료구조로 중복 제거
- **시간복잡도**: O(N)

#### 상한선 비교로 최적값 구하기
"최대한 많이"를 구할 때, 여러 제약 조건의 상한선 중 **최솟값**이 답이 되는 패턴이 있다. 이 문제에서는 종류 수와 N/2 두 가지 상한선이 존재한다.
