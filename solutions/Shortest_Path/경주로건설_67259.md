## 실패한 코드 흐름
1. DFS + 백트래킹으로 모든 경로를 완전탐색
2. (0,0)에서 오른쪽/아래 두 방향으로 각각 DFS 시작
3. 방향이 같으면 +100, 다르면 +600으로 비용 계산
4. 도착점 도달 시 최솟값 갱신

## 실패한 코드
```python
def solution(board):
    answer = 0
    direct = 0
    N = len(board)
    move = [[0, 1], [1, 0], [0, -1], [-1, 0]]
    visited = [[False]*N for i in range(N)]
    answer = float('inf')
    
    
    def dfs(x, y, di, cost):
        if(x == N-1 and y == N-1):
            nonlocal answer
            answer = min(answer, cost)
            return
        
        for ndi in range(4):
            dx, dy = move[ndi]
            nx = x + dx
            ny = y + dy
            if not (0 <= nx < N and 0 <= ny < N and board[nx][ny] == 0 and not visited[nx][ny]):
                continue
            if(ndi == di):
                nCost = cost + 100
            else:
                nCost = cost + 600
            visited[nx][ny] = True
            dfs(nx, ny, ndi, nCost)
            visited[nx][ny] = False
    visited[0][0] = True
    dfs(0, 0, 0, 0)
    dfs(0, 0, 1, 0)
    return answer
```

**문제점**: 로직은 정확하지만 N이 최대 25인 격자에서 모든 경로를 백트래킹하면 경로 수가 기하급수적으로 증가하여 시간 초과 발생

## 풀이 1 - BFS (비용 갱신)

### 흐름
1. 상태를 `(x, y, 방향)`으로 정의하고, 각 상태별 최소 비용을 `cost[x][y][방향]`에 기록
2. 시작점 (0,0)에서 4방향으로 첫 이동을 시도하여 큐에 삽입
3. BFS로 탐색하면서, 같은 방향이면 +100, 다른 방향이면 +600 비용 계산
4. 새로운 비용이 기존 기록보다 작을 때만 갱신하고 큐에 추가 (가지치기)
5. `min(cost[N-1][N-1])`로 도착점의 4방향 중 최솟값 반환

### 코드
```python
from collections import deque

def solution(board):
    N = len(board)
    move = [[0, 1], [1, 0], [0, -1], [-1, 0]]
    cost = [[[float('inf')] * 4 for _ in range(N)] for _ in range(N)]
    q = deque()

    for di in range(4):
        dx, dy = move[di]
        nx, ny = dx, dy
        if 0 <= nx < N and 0 <= ny < N and board[nx][ny] == 0:
            cost[nx][ny][di] = 100
            q.append((nx, ny, di, 100))

    while q:
        x, y, di, c = q.popleft()

        for ndi in range(4):
            dx, dy = move[ndi]
            nx, ny = x + dx, y + dy
            if not (0 <= nx < N and 0 <= ny < N and board[nx][ny] == 0):
                continue
            nCost = c + 100 if ndi == di else c + 600
            if nCost < cost[nx][ny][ndi]:
                cost[nx][ny][ndi] = nCost
                q.append((nx, ny, ndi, nCost))

    return min(cost[N - 1][N - 1])
```

## 풀이 2 - Dijkstra (우선순위 큐)

### 흐름
1. 상태와 비용 관리는 BFS와 동일
2. `heapq`로 비용이 작은 순서대로 처리
3. 꺼낸 상태의 비용이 이미 기록된 값보다 크면 스킵 (Dijkstra 최적화)
4. 비용이 균일하지 않은 그래프에서 정확한 최단 비용을 보장

### 코드
```python
import heapq

def solution(board):
    N = len(board)
    move = [[0, 1], [1, 0], [0, -1], [-1, 0]]
    cost = [[[float('inf')] * 4 for _ in range(N)] for _ in range(N)]
    hq = []

    for di in range(4):
        dx, dy = move[di]
        nx, ny = dx, dy
        if 0 <= nx < N and 0 <= ny < N and board[nx][ny] == 0:
            cost[nx][ny][di] = 100
            heapq.heappush(hq, (100, nx, ny, di))

    while hq:
        c, x, y, di = heapq.heappop(hq)
        if c > cost[x][y][di]:
            continue
        for ndi in range(4):
            dx, dy = move[ndi]
            nx, ny = x + dx, y + dy
            if not (0 <= nx < N and 0 <= ny < N and board[nx][ny] == 0):
                continue
            nCost = c + 100 if ndi == di else c + 600
            if nCost < cost[nx][ny][ndi]:
                cost[nx][ny][ndi] = nCost
                heapq.heappush(hq, (nCost, nx, ny, ndi))

    return min(cost[N - 1][N - 1])
```

## 질문 & 실수 정리

### 새로 배운 것

#### BFS vs Dijkstra 비교
BFS는 간선 비용이 균일할 때 레벨 단위 탐색으로 최단 거리를 보장한다. 하지만 이 문제처럼 비용이 100 또는 600으로 다를 경우, 일반 BFS는 최소 비용 순서로 처리하지 않으므로 같은 칸을 여러 번 갱신할 수 있다. Dijkstra는 우선순위 큐로 항상 최소 비용 상태부터 처리하기 때문에, 한 번 확정된 상태는 다시 갱신되지 않아 더 효율적이다.
- **BFS + 비용 갱신**: 간단한 구현, 작은 N에서 충분. 동일 칸 재방문 가능
- **Dijkstra**: 비균일 비용의 정석. `c > cost[x][y][di]` 스킵으로 불필요한 탐색 제거
- **시간복잡도**: BFS는 최악 O(N² × 4 × 반복갱신), Dijkstra는 O(N² × 4 × log(N² × 4))

#### N값에 따른 알고리즘 선택 (격자 경로 탐색)
격자에서 모든 경로를 탐색하는 백트래킹은 경로 수가 기하급수적으로 증가한다. N이 커질수록 BFS/Dijkstra처럼 상태별 최적값을 기록하는 방식이 필수적이다.
- **N ≤ 10~12**: 백트래킹 가능 (경로 수가 감당 가능한 범위)
- **N ≥ 15**: 백트래킹 시간 초과 위험, BFS/DP/Dijkstra 필요
- **핵심 원리**: visited를 True/False가 아닌 **최소 비용으로 관리**하면 가지치기 효과

#### 상태 확장 (방향 차원 추가)
같은 칸 (x, y)라도 도착 방향에 따라 이후 코너 비용이 달라진다. `cost[x][y][방향]`으로 3차원 상태를 관리하면 방향별 최적 비용을 독립적으로 추적할 수 있다.
- **핵심 원리**: 제약 조건(방향, 벽 부수기 횟수 등)이 이후 비용에 영향을 주면 상태 차원을 추가

### 실수했던 부분

|틀린 것|올바른 것|
|---|---|
|시작 방향을 0(오른쪽)으로 고정|시작점에서 가능한 모든 방향으로 출발해야 함|
|visited[0][0]을 True로 설정하지 않음|DFS 시작 전 시작점 방문 처리 필요|
|N=25 격자에서 백트래킹 시도|N ≥ 15면 BFS/Dijkstra로 전환|
