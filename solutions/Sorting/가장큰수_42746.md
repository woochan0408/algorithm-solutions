## 실패한 코드 흐름

1. 각 숫자를 최대 자릿수에 맞춰 `10^(maxLen - leng)`을 곱해 패딩하는 방식으로 정렬 기준을 만듦
2. 패딩 방식은 `[12, 121]` 같은 케이스에서 이어붙인 결과를 정확히 반영하지 못함 (`12112` vs `12121`)
3. 두 번째 시도에서 O(N²) 그리디로 매번 최적의 수를 찾으려 했으나, 변수 충돌과 구조적 문제 발생

## 실패한 코드

### 시도 1: 자릿수 패딩 정렬
```python
def solution(numbers):
    arr = []
    maxLen = 0
    for number in numbers:
        maxLen = max(maxLen, len(str(number)))
    
    for n in numbers:
        nn = str(n)
        leng = len(nn)
        arr.append((-n * 10**(maxLen-leng), leng, nn))
    
    arr.sort()
    
    result = ''
    for c in arr:
        result += c[2]
    
    return result
```

**문제점**: `10^(maxLen-leng)` 패딩은 이어붙인 결과의 대소를 정확히 반영하지 못함 (예: `[12, 121]` → `"12112"`가 나오지만 정답은 `"12121"`)

### 시도 2: O(N²) 그리디 탐색
```python
def solution(numbers):
    visited = set()
    N = len(numbers)
    result = ''
    
    for i in range(10):
        next = result + str(numbers[0])
        maxIdx = 0
        for i in range(N):
            if(i in visited):
                continue
            
            cur = str(numbers[i])
            if(result + str(cur) > next):
                next = result + cur
                maxIdx = i
                
        visited.add(i)
        result = next
    return result
```

**문제점**: 바깥 루프와 안쪽 루프 변수명 `i` 충돌, `visited.add(i)`가 `maxIdx`가 아닌 안쪽 루프의 마지막 `i`를 추가함. 바깥 루프도 `range(10)` 고정이라 `N`에 대응 못함.

## 성공한 코드 흐름

### 풀이 1: cmp_to_key 비교 함수
1. 모든 숫자를 문자열로 변환
2. 두 수 `a`, `b`를 이어붙인 `a+b`와 `b+a`를 직접 비교하는 커스텀 비교 함수 작성
3. `cmp_to_key`로 정렬에 적용
4. 정렬된 순서대로 이어붙여 결과 반환
5. 모든 수가 0인 경우 `"0"` 반환 처리

### 풀이 2: 문자열 반복 트릭
1. 모든 숫자를 문자열로 변환
2. 원소가 0~1000(최대 4자리)이므로, 문자열을 3번 반복하면 모든 비교에서 자릿수가 맞춰짐
3. 반복된 문자열 기준으로 내림차순 정렬
4. `int` → `str` 변환으로 선행 0 제거

## 성공한 코드

### 풀이 1: cmp_to_key
```python
from functools import cmp_to_key

def solution(numbers):
    nums = list(map(str, numbers))
    
    def compare(a, b):
        if a + b > b + a:
            return -1
        elif a + b < b + a:
            return 1
        else:
            return 0
    
    nums.sort(key=cmp_to_key(compare))
    
    result = ''.join(nums)
    
    if result[0] == '0':
        return '0'
    
    return result
```

### 풀이 2: 문자열 반복 (x*3)
```python
def solution(numbers):
    num = list(map(str, numbers))
    s = sorted(num, key=lambda x: x * 3, reverse=True)
    answer = ''.join(s)
    return str(int(answer))
```

## 질문 & 실수 정리

### 새로 배운 것

#### cmp_to_key
파이썬3에서는 `sort()`에 직접 비교 함수를 넘길 수 없어서 `functools.cmp_to_key`로 비교 함수를 key 함수로 변환해야 한다. 두 원소의 관계를 직접 정의할 수 있어서, 단순 key 변환으로 표현하기 어려운 정렬 기준에 유용하다.
- **핵심 원리**: 비교 함수가 음수면 a 우선, 양수면 b 우선, 0이면 동일
- **시간복잡도**: O(N log N)

#### 문자열 반복 정렬 트릭
문자열을 3번 반복(`x*3`)하면 자릿수 차이로 인한 비교 오류를 해소할 수 있다. 원소의 최대 자릿수가 4자리일 때, 3번 반복하면 최소 3자리 이상이 되어 모든 쌍에서 이어붙인 결과와 동일한 대소 관계가 성립한다.
- **핵심 원리**: `"3"*3 = "333"`, `"30"*3 = "303030"` → 문자열 비교 시 올바른 순서 보장

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| `10^(maxLen-leng)` 패딩으로 비교 | 이어붙인 결과 `a+b vs b+a`를 직접 비교 |
| 바깥/안쪽 루프 변수명 `i` 동일하게 사용 | 서로 다른 변수명 사용 (예: `i`, `j`) |
| `visited.add(i)` → 안쪽 루프의 마지막 `i` 추가 | `visited.add(maxIdx)`로 수정 |
| 바깥 루프 `range(10)` 고정 | `range(N)`으로 수정 |

## AI 코드 리뷰

### 개선할 점

1. **비교 기준의 정확성**: 자릿수 패딩이나 수학적 변환보다 이어붙인 문자열을 직접 비교하는 것이 가장 정확하고 직관적이다.
2. **0으로만 이루어진 입력 처리**: `[0, 0, 0]` → `"000"`이 아닌 `"0"`을 반환해야 한다. `cmp_to_key` 풀이에서는 `result[0] == '0'` 체크, `x*3` 풀이에서는 `str(int(answer))`로 처리.
3. **변수명 충돌 방지**: 중첩 루프에서 같은 변수명을 사용하면 예상치 못한 버그가 발생한다. 항상 다른 변수명을 사용할 것.
