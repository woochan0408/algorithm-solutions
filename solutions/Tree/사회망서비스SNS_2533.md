## 느낀점
>
- 새로운 개념 (트리 + dp) 배우고 싶어서 어거지로 배우면서 풀었다.
- 해당 문제는 어디서든 시작해도 답은 같다.
- 재귀를 통한 DFS 구현은 `sys.setrecursionlimit(10**6)` 꼭 해주기
- dp 문제는 결국 순차 탐색을 어떻게 진행할 지 정하는 것이다.
- 어떻게 정하느냐에 따라 코드 복잡도, 정답 여부가 갈린다.

## 흐름

1. 트리 구조에서 모든 사람이 아이디어를 받아들이도록 하는 최소 얼리어답터 수를 구하는 문제
2. 트리 DP로 접근: 각 노드마다 두 가지 상태(얼리어답터 O/X)를 계산
3. DFS 후위순회로 리프 노드부터 루트까지 값을 채워나감
4. 점화식:
   - `dp[node][0]` = node가 X → 자식들은 전부 O여야 함 → `sum(dp[child][1])`
   - `dp[node][1]` = node가 O → 자식들은 O/X 중 최소 선택 → `sum(min(dp[child][0], dp[child][1])) + 1`
5. 최종 답: `min(dp[root][0], dp[root][1])`

## 코드

```python
import sys
from collections import defaultdict

sys.setrecursionlimit(10**6)
input = sys.stdin.readline

N = int(input())
dp = [[0, 0] for _ in range(N+1)]
graph = defaultdict(list)

for _ in range(N-1):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)

def dfs(node, parent):
    for child in graph[node]:
        if(child != parent):
            dfs(child, node)
            dp[node][0] += dp[child][1]
            dp[node][1] += min(dp[child][0], dp[child][1])
    dp[node][1] += 1

dfs(1, -1)
print(min(dp[1][0], dp[1][1]))
```

## 질문 & 실수 정리

### 질문했던 내용 (새로 배운 것)

| 질문 | 답변 |
|------|------|
| 각 노드의 깊이를 계산해야 하나? | 불필요. DFS 후위순회로 리프→루트 순서 자동 보장 |
| visited 배열 필요한가? | 불필요. `child != parent` 조건이 역할 대체 |
| 트리의 루트는 아무 노드나 가능한가? | 가능. 트리는 원래 루트가 없고 편의상 정하는 것 |

### 트리 DP의 핵심 패턴

**1. 부모-자식 관계는 DFS가 해결**
- `parent` 인자로 부모 전달
- `child != parent` 조건으로 자식만 탐색
- 리프 노드는 따로 찾을 필요 없음 (자식 없으면 자연스럽게 리프)

**2. 계산 순서는 후위순회**
- `dfs(child, node)` 호출 후 → `dp[child]` 이미 계산됨
- 자식 값을 바로 활용해서 부모 값 계산

**3. 각 노드마다 두 상태 계산**
- `dp[node][0]`: 해당 노드가 X일 때 서브트리 최솟값
- `dp[node][1]`: 해당 노드가 O일 때 서브트리 최솟값


### 왜 어디서 시작하든 답이 같은가?

이 문제에서 구하는 건 **"최소 얼리어답터 수"**야. 이건 트리의 **구조적 특성**에 의해 결정되는 값이지, 루트를 어디로 잡느냐와 무관해.

간단한 예시로 보자:

```
    1 — 2 — 3
        |
        4
```

**2를 루트로 잡으면:**
```
        2
      / | \
     1  3  4
```
→ 2만 얼리어답터면 됨 → 답: 1

**1을 루트로 잡으면:**
```
    1
    |
    2
   / \
  3   4
```
→ 여전히 2만 얼리어답터면 됨 → 답: 1

#### 핵심 이유

"모든 비얼리어답터는 인접한 노드가 전부 얼리어답터여야 한다"는 조건은 **간선 기반 조건**이야. 부모-자식 관계가 아니라 **이웃 관계**로 정의된 거지.

트리에서 루트를 바꾸면 부모-자식 방향은 바뀌지만, **간선 자체와 이웃 관계는 안 바뀌어**. 그래서 어떤 노드 집합이 조건을 만족하는지는 루트 선택과 무관하고, 최소 집합의 크기도 동일해.

---

루트가 "없다"는 건 문제에서 루트를 지정 안 해줬다는 뜻이고, 풀이할 때는 **아무 노드나 루트로 잡고 Tree DP 돌리면 된다**는 의미야. 보통 1번을 루트로 잡지.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---------|-----------|
| `dp[node-1]` 사용 | `dp[child]` 사용 (자식 노드를 봐야 함) |
| `dp[node][0] = dp[child][1]` (덮어쓰기) | `dp[node][0] += dp[child][1]` (합산) |
| `+1`을 for문 안에서 | for문 끝나고 한 번만 `dp[node][1] += 1` |
