## 실패한 코드 흐름 1 — BFS 방식
1. 양방향 그래프(defaultdict)에 관계를 추가
2. 매 관계마다 BFS로 연결된 노드 수를 카운트하여 출력

## 실패한 코드 1
```python
from collections import deque, defaultdict
import sys
input = sys.stdin.readline
def solve():
    graph = defaultdict(list)
    N = int(input())
    def bfs(n):
        visited = set()
        visited.add(n)
        dq = deque([n])
        while dq:
            cur = dq.popleft()
            for nxt in graph[cur]:
                if(nxt not in visited):
                    visited.add(nxt)
                    dq.append(nxt)
        return len(visited)
        
    
    for _ in range(N):
        u, v = input().strip().split()
        graph[u].append(v)
        graph[v].append(u)
        print(bfs(u))
T = int(input())
for _ in range(T):
    solve()
```

**문제점**: 매 관계마다 BFS O(V+E)를 수행하므로 총 O(F × F) = O(10¹⁰) → 시간초과

## 실패한 코드 흐름 2 — 딕셔너리 + 리스트 병합 방식
1. `dic`으로 사람 → 네트워크 번호 매핑, `network` 리스트에 인원 저장
2. 관계가 들어올 때 4가지 분기: 둘 다 있음 → 병합, 한쪽만 있음 → 추가, 둘 다 없음 → 새 생성
3. 병합 시 두 네트워크의 모든 인원을 새 방(i)으로 이동
4. BFS 방식(코드 1)과 비교하면 그룹을 직접 관리하는 점이 다르지만, 병합 시 모든 인원을 옮기므로 시간복잡도는 동일하게 O(N²)

## 실패한 코드 2
```python
from collections import deque, defaultdict
import sys
input = sys.stdin.readline
def solve():
    # 사람이름 : network번호
    dic = {}
    N = int(input())
    network = [[] for _ in range(N)]
    for i in range(N):
        u, v = input().strip().split()
        # 둘 다 네트워크를 형성 중이라면
        # 방 하나로 병합
        if(u in dic and v in dic):
            # u가 포함된 네트워크 인원 모두 i방으로 이전
            for key in network[dic[u]]:
                dic[key] = i
                network[i].append(key)
            for key in network[dic[v]]:
                dic[key] = i
                network[i].append(key)
            print(len(network[i]))
                
        # 둘 중 한명이 네트워크 형성된 친구라면
        elif(u in dic):
            network[dic[u]].append(v)
            dic[v] = dic[u]
            print(len(network[dic[u]]))
        elif(v in dic):
            network[dic[v]].append(u)
            dic[u] = dic[v]
            print(len(network[dic[v]]))
            
        #어느 곳에도 해당 안 되면 -> 새 네트워크 생성 (번호는 i)
        else:
            dic[u] = i
            dic[v] = i
            network[i].append(u)
            network[i].append(v)
            print(2)
            
T = int(input())
for _ in range(T):
    solve()
```

**문제점**: 병합 시 모든 인원을 하나씩 옮기므로 최악 O(N)이 매번 발생 → 총 O(N²) = O(10¹⁰). 그룹 관리 아이디어는 유니온파인드와 같은 방향이지만, "인원을 직접 옮기는" 구현이 병목이다.

## 성공한 코드 흐름
1. 딕셔너리 기반 유니온파인드 구성 (parent, size)
2. 새 이름이 등장하면 parent[이름] = 자기자신, size = 1로 초기화
3. 매 친구 관계마다 union 수행 후, find로 루트를 찾아 size 출력
4. find에서 경로 압축, union에서 size 기준 합치기로 거의 O(1) 연산

## 성공한 코드
```python
from collections import deque, defaultdict
import sys
input = sys.stdin.readline
def solve():
    N = int(input())
    parent = {}
    size = {}
    def find(name):
        if(parent[name] != name):
            parent[name] = find(parent[name])
        return parent[name]
    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return
        if(size[a] < size[b]):
            a, b = b, a
        parent[b] = a
            
        size[a] += size[b]
    for i in range(N):
        u, v = input().strip().split()
        if u not in parent:
            parent[u] = u
            size[u] = 1
        if v not in parent:
            parent[v] = v
            size[v] = 1
        union(u, v)
        print(size[find(u)])
T = int(input())
for _ in range(T):
    solve()
```

## 질문 & 실수 정리

### 새로 배운 것

#### 유니온파인드 (Union-Find)
서로소 집합을 관리하는 자료구조로, "같은 그룹인지 확인(find)"과 "두 그룹 합치기(union)"를 거의 O(1)에 처리한다. 각 노드가 부모를 가리키는 트리 구조로, 그룹 전체를 옮기지 않고 루트끼리 연결하는 것이 핵심이다.
- **핵심 원리**: 대표(루트) 노드를 따라가며 같은 집합인지 판별, 합칠 때는 루트끼리 연결
- **시간복잡도**: O(α(N)) ≈ O(1) (아커만 역함수)

#### 경로 압축 (Path Compression)
find 호출 시 거쳐가는 모든 노드의 parent를 루트로 직접 연결하는 최적화 기법. 다음 find 호출 시 바로 루트에 접근할 수 있어진다.
- **핵심 원리**: `parent[x] = find(parent[x])`로 재귀 복귀 시 루트를 직접 가리키게 갱신

#### Union by Size
합칠 때 항상 작은 그룹을 큰 그룹 밑에 붙여서 트리가 편향되는 것을 방지한다. 큰 쪽이 루트가 되어야 영향받는 노드 수가 최소화된다.
- **핵심 원리**: size가 큰 쪽을 루트로 유지, 작은 쪽의 parent를 큰 쪽으로 변경

#### size는 루트에서만 유효
size 배열은 루트 노드에만 정확한 값이 저장된다. 따라서 그룹 크기를 조회할 때 `size[u]`가 아니라 반드시 `size[find(u)]`로 루트를 찾아서 조회해야 한다.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
|---|---|
| `def union(a, b):` 안에서 `find(a)`, `find(b)` (매개변수와 지역변수명 충돌) | 매개변수명과 find 인자를 일치시키거나 다른 변수에 할당 |
| `size[a] += 1` (rank처럼 1만 증가) | `size[a] += size[b]` (상대 그룹 인원 전체를 더해야 함) |
| size 합산을 `if(size[a] == size[b]):` 안에 넣음 | 크기가 다를 때도 합쳐야 하므로 조건 없이 항상 실행 |

## AI 코드 리뷰

### 개선할 점

1. **미사용 import 제거**: `deque`, `defaultdict`는 이전 풀이에서 쓰던 것으로 현재 코드에서 사용하지 않는다.
2. **이름 초기화 함수 분리**: 이름 등록 로직이 for문 안에 반복되므로 함수로 분리하면 가독성이 좋아진다.
3. **재귀 find → 반복 find 고려**: Python은 재귀 깊이 제한이 있어 반복문 방식이 더 안전하다. 이 문제에서는 union by size로 트리 깊이가 O(log N)이라 괜찮지만, 습관적으로 반복문을 쓰면 안전하다.
4. **미사용 변수 제거**: `for i in range(N)`에서 `i`를 사용하지 않으므로 `_`로 바꾸면 의도가 명확하다.

import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    parent = {}
    size = {}

    def init(name):
        if name not in parent:
            parent[name] = name
            size[name] = 1

    def find(name):
        if parent[name] != name:
            parent[name] = find(parent[name])
        return parent[name]

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]

    for _ in range(N):
        u, v = input().split()
        init(u)
        init(v)
        union(u, v)
        print(size[find(u)])

T = int(input())
for _ in range(T):
    solve()
