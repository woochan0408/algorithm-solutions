## 느낀점
> 
- 문제 이해를 못 했다.
- 유니온 파인트 기초 다지기 좋은 문제.

## 흐름
1. 노드 수(N)와 간선 수(M)를 입력받는다.
2. 문제에서 주어진 친분 관계는 사이클이 없는 포레스트(독립된 여러 트리) 형태이므로, 각 트리(그룹)의 노드 개수를 모두 곱하면 전체 경우의 수가 된다.
3. 유니온 파인드(Union-Find)를 사용하여 간선을 연결한다. 이때 작은 트리를 큰 트리 아래에 붙이면서(`Union by Size`), 그룹의 루트 노드에 속한 총인원수를 갱신한다.
4. 연결이 모두 끝난 후, 1번부터 N번 노드까지 순회하며 본인이 그룹의 대표(루트 노드, `i == parent[i]`)인 경우에만 해당 그룹의 크기(`size[i]`)를 결과 변수에 곱해준다.
5. 계산 과정에서 $1\,000\,000\,007$로 나눈 나머지를 유지하며 최종 결과를 출력한다.

## 코드
```python
import sys
input = sys.stdin.readline

N, M = map(int, input().split())
parent = list(range(N+1))
size=  [1]*(N+1)

def find(n):
    if(n != parent[n]):
        parent[n] = find(parent[n])
    return parent[n]

def union(a, b):
    a = find(a)
    b = find(b)

    if(a != b):
        if(size[a] > size[b]):
            parent[b] = a
            size[a] += size[b]
        else:
            parent[a] = b
            size[b] += size[a]
            
for i in range(M):
    u, v = map(int, input().split())
    union(u, v)

result = 1
for i in range(N+1):
    if(i == parent[i]):
        result *= size[i]
        result %= 1_000_000_007
print(result)

```

## 질문 & 실수 정리

### 새로 배운 것

#### Union by Size

유니온 파인드에서 두 트리를 합칠 때, 항상 '크기가 작은 트리를 큰 트리 밑으로' 붙이는 최적화 기법. 트리의 편향(한쪽으로 길어짐)을 막아 트리의 높이를 낮게 유지할 수 있으며, 루트 노드의 `size` 배열에 해당 그룹의 총 노드 개수를 효과적으로 저장할 수 있다.

### 실수했던 부분

| 틀린 것 | 올바른 것 |
| --- | --- |
| `parent = [range(N+1)]` (range 객체가 요소 1개로 들어감) | `parent = list(range(N+1))` (0~N까지의 리스트로 초기화) |
| `for i in range(M+1):` (M번만 받아야 하는데 M+1번 대기하여 에러 발생) | `for _ in range(M):` |
| `size` 배열의 모든 요소를 다 곱해버림 | `if i == parent[i]:` 조건으로 루트 노드의 `size`만 곱함 |

## AI 코드 리뷰

### 개선할 점

1. **사용하지 않는 0번 노드 제외**: 노드 번호는 1번부터 주어집니다. 마지막 정답을 구할 때 `for i in range(N+1):`로 돌면 0번 노드(부모가 0, 사이즈가 1)도 체크하게 됩니다. 어차피 1을 곱하는 거라 정답에는 영향이 없지만, 정확성을 위해 `for i in range(1, N+1):`로 수정하는 것이 좋습니다.
2. **안전한 재귀 한도 설정**: 파이썬은 기본 재귀 깊이 제한이 1000입니다. `Union by Size`를 적용했기에 트리가 깊어질 확률은 매우 낮지만, 파이썬으로 재귀(find 함수)를 다룰 때는 항상 `sys.setrecursionlimit(10**6)` 정도를 최상단에 추가하는 습관을 들이는 것이 안전합니다.

## 수정된 코드

```python
# 기존 Union-Find 코드 개선본
import sys
sys.setrecursionlimit(300000)
input = sys.stdin.readline

N, M = map(int, input().split())
parent = list(range(N+1))
size = [1] * (N+1)

def find(n):
    if n != parent[n]:
        parent[n] = find(parent[n])
    return parent[n]

def union(a, b):
    a = find(a)
    b = find(b)

    if a != b:
        if size[a] > size[b]:
            parent[b] = a
            size[a] += size[b]
        else:
            parent[a] = b
            size[b] += size[a]
            
for _ in range(M):
    u, v = map(int, input().split())
    union(u, v)

result = 1
# 1번 노드부터 순회
for i in range(1, N+1):
    if i == parent[i]:
        result *= size[i]
        result %= 1_000_000_007

print(result)

```
### 다른 풀이: BFS (너비 우선 탐색)

유니온 파인드 외에 **그래프 탐색(BFS/DFS)**을 통해서도 쉽게 해결할 수 있습니다.

* **흐름**: 1번 노드부터 N번 노드까지 순회하면서, 아직 방문하지 않은 노드라면 BFS를 시작합니다. 큐가 빌 때까지 연결된 노드를 돌면서 '방문한 노드 개수(그룹 인원수)'를 카운트하여 반환하고, 이 값들을 곱해주면 됩니다.


#### BFS 풀이 코드

```python
import sys
from collections import deque
input = sys.stdin.readline

N, M = map(int, input().split())
graph = [[] for _ in range(N + 1)]
visited = [False] * (N + 1)

# 양방향 간선 연결
for _ in range(M):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)

def bfs(start):
    queue = deque([start])
    visited[start] = True
    count = 1  # 현재 그룹의 인원수
    
    while queue:
        curr = queue.popleft()
        for nxt in graph[curr]:
            if not visited[nxt]:
                visited[nxt] = True
                queue.append(nxt)
                count += 1
    return count

result = 1
for i in range(1, N + 1):
    if not visited[i]:  # 방문하지 않은 새로운 그룹 발견 시
        size = bfs(i)
        result = (result * size) % 1_000_000_007

print(result)

```
